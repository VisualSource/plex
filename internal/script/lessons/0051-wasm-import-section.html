Lesson 51 – The WASM Import Section

Previous: Lesson 50 – arr.remove in the Binary Backend

So far every plex function has been self-contained: the module produces values, and the test harness reads them. But real programs need to do things — print output, read input, call a clock. WASM cannot do any of these by itself; it depends entirely on functions provided by the host. This lesson wires up that link.

The Import Section in the WASM Binary Format

A WASM module may import functions, globals, tables, or memories from the host. Each import carries three pieces of information:

  • module name — a string identifying the host namespace (e.g. "plex:console")
  • field name — the specific export within that namespace (e.g. "print")
  • description — what is being imported: for a function, a type index into the type section

The import section has section ID 0x02 and must appear before the function section.

§1 type ← all type signatures (imports AND locals) §2 import ← imported functions point at type indices in §1 §3 function ← local functions point at type indices in §1 §7 export §10 code ← bodies for local functions only (not imports)

The Critical Constraint: Import Indices Come First

Every function in a WASM module occupies a function index. The key rule is:

Imported functions occupy the lowest indices. Local functions are indexed starting at numImports.

If a module imports 1 function and defines 3 local functions:

func index 0 ← import[0] e.g. "plex:console"."print" func index 1 ← local[0] first locally defined function func index 2 ← local[1] func index 3 ← local[2]

Every call instruction uses these absolute indices. If the compiler assigns local functions indices 0, 1, 2 and later adds an import at index 0, every existing call is wrong. The fix: decide how many imports exist before assigning local indices.

How Plex Declares Imports

The plex grammar for imports (already parsed):

import print from "plex:console";

The typechecker's modules.go already recognises "plex:console" and registers print as a function taking one string (= i32 pointer) and returning void. The binary backend simply needs to trust that declaration and emit the right bytes.

The importSig Struct

type importSig struct {
    modName   string  // e.g. "plex:console"
    fieldName string  // e.g. "print"
    funcName  string  // as called in plex code
    params    []byte
    results   []byte
}

collectImports

func collectImports(p *script.Program) []importSig {
    var out []importSig
    for _, stmt := range p.Stmts {
        imp, ok := stmt.(*script.ImportStatement)
        if !ok {
            continue
        }
        switch imp.Source {
        case "plex:console":
            for _, name := range imp.Imports {
                if name == "print" {
                    out = append(out, importSig{
                        modName:   imp.Source,
                        fieldName: name,
                        funcName:  name,
                        params:    []byte{ValI32}, // string pointer
                        results:   nil,             // void
                    })
                }
            }
        }
    }
    return out
}
Why only ValI32 for a string? In plex's memory model, a string is an i32 pointer into linear memory — exactly the same encoding as an array or struct pointer. The actual string bytes live at ptr+4 with length at ptr+0. The host's print function receives that pointer and reads the string out of the WASM memory.

encodeImportSection

In section.go, add:

func encodeImportSection(imports []importSig) []byte {
    var body []byte
    body = AppendULEB128(body, uint32(len(imports)))
    for i, imp := range imports {
        body = encodeName(body, imp.modName)
        body = encodeName(body, imp.fieldName)
        body = append(body, 0x00)                 // kind: function
        body = AppendULEB128(body, uint32(i))      // type index (imports come first in type section)
    }
    return section(SectionImport, body)
}

Also update encodeFunctionSection to accept a typeOffset:

func encodeFunctionSection(sigs []funcSig, typeOffset uint32) []byte {
    var body []byte
    body = AppendULEB128(body, uint32(len(sigs)))
    for i := range sigs {
        body = AppendULEB128(body, typeOffset+uint32(i))  // type index with offset
    }
    return section(SectionFunction, body)
}

Updating module.go

The full flow in module.go:

func CompileProgram(node *script.Program) ([]byte, error) {
    if err := typeschecker.Check(node); err != nil {
        return nil, err
    }

    strings := collectStrings(node)
    structs := collectStructs(node)
    imports := collectImports(node)          // NEW

    sigs, funcs, exports, err := collectSignatures(node)
    if err != nil { return nil, err }

    needsHeap := len(strings.entries) > 0 || programHasHeapAllocation(node, structs)
    if needsHeap {
        exports = append(exports, exportEntry{name: "memory", kind: ExportMemory, idx: 0})
        exports = append(exports, exportEntry{name: "__heap_ptr", kind: ExportGlobal, idx: 0})
    }

    // Build the unified function index map: imports first, then locals.
    importOffset := uint32(len(imports))
    funcIndexes := make(map[string]uint32, len(imports)+len(sigs))
    for i, imp := range imports {
        funcIndexes[imp.funcName] = uint32(i)
    }
    for i, s := range sigs {
        funcIndexes[s.name] = importOffset + uint32(i)
    }

    // Build the type section: import types first, then local types.
    allSigs := make([]funcSig, 0, len(imports)+len(sigs))
    for _, imp := range imports {
        allSigs = append(allSigs, funcSig{
            name:    imp.funcName,
            params:  imp.params,
            results: imp.results,
        })
    }
    allSigs = append(allSigs, sigs...)

    var out []byte
    out = append(out, magic...)
    out = append(out, version...)

    if len(allSigs) > 0 {
        out = append(out, encodeTypeSection(allSigs)...)
        if len(imports) > 0 {
            out = append(out, encodeImportSection(imports)...)   // NEW — before function section
        }
        out = append(out, encodeFunctionSection(sigs, importOffset)...)  // CHANGED — pass offset

        if needsHeap {
            out = append(out, encodeMemorySection()...)
            out = append(out, encodeGlobalSection(strings.next)...)
        }
        if len(exports) > 0 {
            out = append(out, encodeExportSection(exports)...)
        }

        code, err := encodeCodeSection(funcs, sigs, funcIndexes, strings, structs)
        if err != nil { return nil, err }
        out = append(out, code...)

        if len(strings.entries) > 0 {
            out = append(out, encodeDataSection(strings)...)
        }
    }
    return out, nil
}
Export index adjustment for memory/global The existing exports for "memory" (ExportMemory, idx: 0) and "__heap_ptr" (ExportGlobal, idx: 0) use indices into the memory and global spaces, not the function space. These are unaffected by the import offset. Only function export indices would need adjustment — and currently all exported functions are built in collectSignatures using len(funcs) at collection time, which produces local-only indices. After adding the import offset in funcIndexes, you also need to fix the export entries emitted by collectSignatures. The cleanest fix: build export indices from funcIndexes after the map is complete, not during collection.

Fixing Export Indices

collectSignatures currently sets idx: uint32(len(funcs)) which gives a local-relative index (0, 1, 2, …). After we add an import offset, that's wrong. The fix is to not set idx during collection and instead fill it in after funcIndexes is built: 

// In module.go, after funcIndexes is built:
for i := range exports {
    if exports[i].kind == ExportFunc {
        exports[i].idx = funcIndexes[exports[i].name]
    }
}

This requires that exportEntry stores the function name, not just the index. Add a name field to exportEntry (it already has name for the export key — you can reuse it, since the plex function name is the export name).

A simpler approach: since collectSignatures already stores the function declaration, you can pass the fully-built funcIndexes map to a second pass that builds exports.

func TestEndToEnd_Import_Print(t *testing.T) {
    src := `
        import print from "plex:console";
        fn say_hello() {
            print("hello");
        }
    `
    ast, err := script.Parse(strings.NewReader(src))
    if err != nil { t.Fatal(err) }

    wasm, err := binary_wasm.CompileProgram(ast)
    if err != nil { t.Fatal(err) }

    ctx := t.Context()
    r := wazero.NewRuntime(ctx)
    defer r.Close(ctx)

    var gotPtr uint32
    _, err = r.NewHostModuleBuilder("plex:console").
        NewFunctionBuilder().
        WithFunc(func(ctx context.Context, m api.Module, ptr uint32) {
            gotPtr = ptr
        }).
        Export("print").
        Instantiate(ctx)
    if err != nil { t.Fatal(err) }

    mod, err := r.Instantiate(ctx, wasm)
    if err != nil { t.Fatalf("instantiate: %v", err) }

    _, err = mod.ExportedFunction("say_hello").Call(ctx)
    if err != nil { t.Fatalf("call: %v", err) }

    if gotPtr == 0 {
        t.Fatal("print was never called")
    }

    // Read the string out of WASM memory to verify content
    mem := mod.Memory()
    n, _ := mem.ReadUint32Le(gotPtr)
    data, _ := mem.Read(gotPtr+4, n)
    if string(data) != "hello" {
        t.Fatalf("got %q, want \"hello\"", string(data))
    }
}
