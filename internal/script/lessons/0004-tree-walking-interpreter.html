The parser produces an AST. The interpreter walks that tree and computes a result for each node. It's recursive in the same way the parser was — each node type has a dedicated eval case, and compound nodes (like BinaryExpression) eval their children first.

Part 1: Values

The interpreter needs a runtime representation of every value the language can produce. In a typed language you'd track the type too; for now, a Go interface with concrete types works cleanly:

type Value interface {
    String() string   // for printing
    Truthy() bool    // for if/while conditions
}

type NumberValue struct{ V float64 }
type StringValue struct{ V string }
type BoolValue   struct{ V bool }
type NullValue   struct{}

func (n NumberValue) Truthy() bool { return n.V != 0 }
func (s StringValue) Truthy() bool { return s.V != "" }
func (b BoolValue)   Truthy() bool { return b.V }
func (n NullValue)   Truthy() bool { return false }

func (n NumberValue) String() string { return fmt.Sprintf("%g", n.V) }
func (s StringValue) String() string { return s.V }
func (b BoolValue)   String() string { return fmt.Sprintf("%v", b.V) }
func (n NullValue)   String() string { return "null" }

type FunctionValue struct {
    Params []AstNode    // the Parameter nodes from the AST
    Body   AstNode      // the Block node
    Env    *Environment // the closure — captures defining scope
}
func (f FunctionValue) Truthy() bool    { return true }
func (f FunctionValue) String() string { return "<fn>" }
FunctionValue captures its environment
The Env field on FunctionValue is what makes closures work. When a function is declared, it captures the environment at that point. When called, it creates a child scope of that captured environment — not of the call site. This is how inner functions can see outer variables even after the outer function returns.

Part 2: The Environment

Variables live in an environment — a map from name to value. Nested scopes (function bodies, blocks) get child environments that delegate lookups to their parent:

type Environment struct {
    vars   map[string]Value
    parent *Environment
}

func NewEnvironment(parent *Environment) *Environment {
    return &Environment{vars: make(map[string]Value), parent: parent}
}

func (e *Environment) Get(name string) (Value, bool) {
    v, ok := e.vars[name]
    if !ok && e.parent != nil {
        return e.parent.Get(name) // walk up the chain
    }
    return v, ok
}

func (e *Environment) Set(name string, v Value) {
    e.vars[name] = v
}

func (e *Environment) Assign(name string, v Value) bool {
    if _, ok := e.vars[name]; ok {
        e.vars[name] = v
        return true
    }
    if e.parent != nil {
        return e.parent.Assign(name, v) // mutate the scope that owns it
    }
    return false
}

Notice the distinction between Set and Assign. Set declares a new variable in the current scope. Assign walks up to find an existing binding and mutates it there. Without this split, x = 1 inside a function would shadow the outer x instead of updating it.

Part 3: The Eval Function

The evaluator is a single function with a type switch — exactly like the parser's statement dispatcher, but over AST node types instead of tokens:

func Eval(node AstNode, env *Environment) (Value, error) {
    switch n := node.(type) {

    case *Program:
        var result Value = NullValue{}
        for _, stmt := range n.Stmts {
            v, err := Eval(stmt, env)
            if err != nil { return nil, err }
            result = v
        }
        return result, nil

    case *NumberLiteral:
        f, err := strconv.ParseFloat(n.Value, 64)
        if err != nil { return nil, err }
        return NumberValue{V: f}, nil

    case *Identifier:
        v, ok := env.Get(n.Value)
        if !ok {
            return nil, fmt.Errorf("undefined: %s", n.Value)
        }
        return v, nil

    case *VariableDeclaration:
        val, err := Eval(n.Init, env)
        if err != nil { return nil, err }
        env.Set(n.Name, val)
        return NullValue{}, nil

    case *AssignmentExpression:
        val, err := Eval(n.Value, env)
        if err != nil { return nil, err }
        if !env.Assign(n.Name, val) {
            return nil, fmt.Errorf("assign to undefined: %s", n.Name)
        }
        return val, nil

    case *BinaryExpression:
        return evalBinary(n, env)

    case *IfStatement:
        cond, err := Eval(n.Condition, env)
        if err != nil { return nil, err }
        if cond.Truthy() {
            return Eval(n.Body, env)
        } else if n.Else != nil {
            return Eval(n.Else, env)
        }
        return NullValue{}, nil

    case *Block:
        child := NewEnvironment(env) // new scope for the block
        var result Value = NullValue{}
        for _, stmt := range n.Stmts {
            v, err := Eval(stmt, child)
            if err != nil { return nil, err }
            result = v
        }
        return result, nil

    default:
        return nil, fmt.Errorf("eval: unhandled node %T", node)
    }
}

Part 4: Binary Operations

func evalBinary(n *BinaryExpression, env *Environment) (Value, error) {
    left, err := Eval(n.Left, env)
    if err != nil { return nil, err }
    right, err := Eval(n.Right, env)
    if err != nil { return nil, err }

    lv, lok := left.(NumberValue)
    rv, rok := right.(NumberValue)

    switch n.Operator {
    case TokenType_Plus:
        if lok && rok { return NumberValue{V: lv.V + rv.V}, nil }
        return StringValue{V: left.String() + right.String()}, nil // string concat
    case TokenType_Minus:
        if !lok || !rok { return nil, fmt.Errorf("- requires numbers") }
        return NumberValue{V: lv.V - rv.V}, nil
    case TokenType_Star:
        if !lok || !rok { return nil, fmt.Errorf("* requires numbers") }
        return NumberValue{V: lv.V * rv.V}, nil
    case TokenType_EqualEqual:
        return BoolValue{V: left.String() == right.String()}, nil
    case TokenType_LessThen:
        if !lok || !rok { return nil, fmt.Errorf("< requires numbers") }
        return BoolValue{V: lv.V < rv.V}, nil
    default:
        return nil, fmt.Errorf("unknown operator: %v", n.Operator)
    }
}

Part 5: The Hard Part — Return

Here's the problem. return needs to escape from wherever it appears — possibly deep inside nested blocks and loops — all the way back to the function call that should receive the value. Go's normal error propagation would need every caller to check "is this a return?" at every level.

The clean solution: a sentinel error type that carries the return value. It's technically an error, but it's not an error — it's a signal.

type returnSignal struct { value Value }
func (r returnSignal) Error() string { return "return" }

The ReturnStatement case in Eval wraps the value in this signal:

case *ReturnStatement:
    if n.Value == nil {
        return nil, returnSignal{value: NullValue{}}
    }
    val, err := Eval(n.Value, env)
    if err != nil { return nil, err }
    return nil, returnSignal{value: val}

The function call handler is the only place that catches this signal. Everything else just propagates it:

case *FunctionCall:
    calleeVal, err := Eval(n.Callee, env)
    if err != nil { return nil, err }
    fn, ok := calleeVal.(FunctionValue)
    if !ok { return nil, fmt.Errorf("not a function") }

    // build the call environment as a child of the closure's env
    callEnv := NewEnvironment(fn.Env)
    for i, param := range fn.Params {
        p := param.(*Parameter)
        arg, err := Eval(n.Args[i], env)
        if err != nil { return nil, err }
        callEnv.Set(p.Name, arg)
    }

    _, err = Eval(fn.Body, callEnv)
    if err != nil {
        if ret, ok := err.(returnSignal); ok {
            return ret.value, nil // unwrap the signal here — only here
        }
        return nil, err // real error — propagate
    }
    return NullValue{}, nil
Why not use panic/recover?
Go's panic/recover would also work. But sentinel errors are explicit — the type system proves you handle them, and they compose cleanly with real errors. You'll use the same pattern for break and continue in while loops later.
