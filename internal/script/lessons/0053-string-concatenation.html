Lesson 53 – String Concatenation

Previous: Lesson 52 – The export Keyword

The plex interpreter handles "hello" + " world" trivially — just concatenate the Go strings. The binary backend is different: it must emit WASM instructions that allocate a new region on the heap, copy both strings' bytes into it, and leave an i32 pointer as the result. This lesson adds that capability.

The Current Gap

Try to compile this plex program today:

export fn greet(): string {
    return "hello" + " world";
}

The compiler will error: no opcode for string +. Tracing why shows a design tension in the current BinaryExpression handler.

The current handler flow

// body.go — simplified
case *script.BinaryExpression:
    if short-circuit { ... }
    b.walk(n.Left)   // ← both operands already evaluated before type check
    b.walk(n.Right)
    opType := leftExpr.GetType()
    ...
    arithOpcode(opType.Kind, n.Operator)  // ← errors for TypeKind_String

The problem: both operands are walked before the type is inspected. For numeric types this is fine — the result opcode is trivially applied to two stack values. But string concatenation needs a completely different strategy: save the two pointers to locals, read lengths, allocate, copy. You can't do that if the stack already has the two pointers sitting there from the walk.

The fix is to extract the type before the walk, so a string-typed + can take its own code path from the start.

WASM Bulk Memory: memory.copy

Copying bytes from one region to another inside WASM linear memory once required a hand-written loop. Since WASM 2.0 (standardised in 2022 and supported by default in wazero), the bulk memory proposal adds memory.copy — a single instruction that handles the entire copy: 

; memory.copy dst src len
; copies len bytes from memory[src..src+len] to memory[dst..dst+len]
FC 0A 00 00   ; opcode prefix + copy opcode + dst_memidx=0 + src_memidx=0

In binary: the miscellaneous prefix byte 0xFC signals a multi-byte opcode, then 0x0A is the memory.copy code, and the two trailing 0x00 bytes are the destination and source memory indices (always 0 in single-memory modules).

Stack convention: memory.copy pops (dst i32) (src i32) (len i32) — dst is pushed first, then src, then len.

Plex String Memory Layout (Review)

Every plex string is stored in the heap as:

offset +0 len ← i32, number of bytes in the string offset +4 byte₀ +5 byte₁ … +4+len-1 byteₙ₋₁

For "ab" + "c", the result needs:

  • 4 bytes for length (= 3)
  • 3 bytes for content: 'a', 'b', 'c'

Total: 7 bytes allocated on the heap.

The walkStringConcat Strategy

Five synthetic locals are needed. Each is declared with addSyntheticLocal(ValI32) at the top of the function, so the local section is correct before any body bytes reference them.

LocalTypeHolds
leftPtri32pointer to the left string
rightPtri32pointer to the right string
leftLeni32byte count of the left string
rightLeni32byte count of the right string
resultPtri32pointer to the new concatenated string

Phase 1 — Evaluate operands, save pointers

; evaluate left → i32 ptr
walk(n.Left)
21 leftPtr     ; local.set leftPtr

; evaluate right → i32 ptr
walk(n.Right)
21 rightPtr    ; local.set rightPtr

Phase 2 — Read lengths

; leftLen = i32 at leftPtr+0
20 leftPtr     ; local.get leftPtr

21 leftLen     ; local.set leftLen

; rightLen = i32 at rightPtr+0
20 rightPtr
28 02 00
21 rightLen

Phase 3 — Allocate and write the length

; resultPtr = current __heap_ptr  (global 0)
23 00         ; global.get 0   → stack: [heapPtr]
22 resultPtr  ; local.tee resultPtr  → stack: [heapPtr]  (copy saved)

; memory[resultPtr+0] = leftLen + rightLen
20 leftLen    ; stack: [resultPtr, leftLen]
20 rightLen
6A            ; i32.add  → stack: [resultPtr, newLen]
36 02 00      ; i32.store align=2 offset=0  → stores newLen at resultPtr, stack: []

; bump __heap_ptr = resultPtr + 4 + leftLen + rightLen
20 resultPtr
41 04         ; i32.const 4
6A            ; i32.add
20 leftLen
6A
20 rightLen
6A
24 00         ; global.set 0

Phase 4 — Copy bytes

; memory.copy(resultPtr+4, leftPtr+4, leftLen)
20 resultPtr  ; dst
41 04
6A
20 leftPtr    ; src
41 04
6A
20 leftLen    ; len
FC 0A 00 00   ; memory.copy

; memory.copy(resultPtr+4+leftLen, rightPtr+4, rightLen)
20 resultPtr  ; dst = resultPtr + 4 + leftLen
41 04
6A
20 leftLen
6A
20 rightPtr   ; src = rightPtr + 4
41 04
6A

FC 0A 00 00

; push result value
20 resultPtr
Why local.tee instead of local.set + local.get? — local.tee (0x22) is the "tee" from Unix pipes: it stores the top-of-stack value into a local without consuming it. The value stays on the stack to be used as the destination address for the immediately following i32.store. Using local.set then local.get would require two instructions and the same effect; local.tee saves one.

Restructuring BinaryExpression in body.go

The key refactor: move the type extraction before the walk, and add a string-concat early exit:

case *script.BinaryExpression:
    if n.Operator == script.TokenType_AND || n.Operator == script.TokenType_OR {
        return b.walkShortCircuit(n)
    }

        // Extract type BEFORE walking — string concat needs a separate path
        leftExpr, ok := n.Left.(script.Expression)
        if !ok {
            return fmt.Errorf("binary expression left has no type info")
        }
        opType := leftExpr.GetType()
        if opType == nil {
            return fmt.Errorf("no type on binary expression operand")
        }
        if opType.Kind == script.TypeKind_String && n.Operator == script.TokenType_Plus {
            return b.walkStringConcat(n)
        }

    if err := b.walk(n.Left); err != nil { return err }
    if err := b.walk(n.Right); err != nil { return err }

    // opType already computed above — remove the duplicate extraction below

    if isCmpOp(n.Operator) { ... }
    op, err := arithOpcode(opType.Kind, n.Operator)
    ...
Remove the duplicate type extraction. The current code extracts leftExpr and opType after the walk calls. After this refactor, those same variables exist before the walk. Delete the old extraction lines — otherwise you get a compile error (redeclared variable) or a redundant extraction.

func TestEndToEnd_StringConcat(t *testing.T) {
    src := `
        export fn greet(): string {
            return "hello" + " world";
        }
    `

    ctx := t.Context()

}
