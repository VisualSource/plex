1. Why explicit casts are needed

Plex is statically typed. Every arithmetic operation requires operands of the same type. This compiles fine:

let x: i64 = 5;
let y: i64 = x + 3;

But this fails type-checking:

let x: i64 = 5;
let y: f64 = x + 3.0;  // type error: i64 + f64

With an as cast the programmer states their intent explicitly, and the compiler emits the right WAT instruction:

let y: f64 = (x as f64) + 3.0;  // ok

2. WAT's numeric conversion instructions

WAT has no implicit coercions. Every type boundary requires an explicit instruction. The instruction names reflect what actually happens to the bits:

FromToWAT instructionWhat happens
i32i64i64.extend_i32_sSign-extends 32 bits to 64 (fills upper bits with sign bit)
i64i32i32.wrap_i64Keeps low 32 bits, discards high 32 (wraps around on overflow)
i32f32f32.convert_i32_sNearest IEEE 754 float to the integer value
i32f64f64.convert_i32_sExact (all i32 values fit in f64)
i64f32f32.convert_i64_sMay lose precision (f32 has 24-bit significand)
i64f64f64.convert_i64_sMay lose precision (f64 has 53-bit significand, i64 has 63)
f32f64f64.promote_f32Exact widening (every f32 is representable as f64)
f64f32f32.demote_f64May lose precision or become ±Infinity
f32i32i32.trunc_f32_sTruncates toward zero; traps if NaN or out of range
f32i64i64.trunc_f32_sSame, 64-bit result
f64i32i32.trunc_f64_sTruncates toward zero; traps if NaN or out of range
f64i64i64.trunc_f64_sSame, 64-bit result
Instruction taxonomy
  • extend — widen an integer, preserving the signed value
  • wrap — narrow an integer, discarding high bits (the value "wraps")
  • convert — integer to float, nearest representable value
  • promote / demote — float ↔ float width change
  • trunc — float to integer, truncating toward zero (dangerous: traps on NaN/overflow)
trunc traps — i64.trunc_f64_s on NaN, +Inf, or any value outside [−2⁶³, 2⁶³−1] causes a WebAssembly trap (runtime exception). This is a deliberate choice — plex doesn't silently produce garbage for undefined behavior. A future saturating_cast could use i64.trunc_sat_f64_s instead.

Plex maps int → i64 and float → f64. For the compiler, normalise these before the lookup:

func normaliseWasm(t *script.Type) string {
    switch t.Kind {
    case script.TypeKind_Int,   script.TypeKind_I64: return "i64"
    case script.TypeKind_Float, script.TypeKind_F64: return "f64"
    case script.TypeKind_I32:                        return "i32"
    case script.TypeKind_F32:                        return "f32"
    default:                                         return ""
    }
}

Task A2 — parser (ast.go): add parseCast

The grammar rule is: cast ::= unary ("as" typeExpr)?

Add a new function parseCast that sits between parsePower and parseUnary:

func (p *Parser) parseCast() (AstNode, error) {
    expr, err := p.parseUnary()
    if err != nil {
        return nil, err
    }

    if !isKeyword(p.peek(), "as") {
        return expr, nil
    }
    p.advance() // consume "as"

    targetType, err := p.parseTypeExpr()
    if err != nil {
        return nil, err
    }

    start, _ := expr.Range()
    _, end  := targetType.Range()

    return &CastExpression{
        Start:      start,
        End:        end,
        Expr:       expr,
        TargetType: targetType,
    }, nil
}

Then update parsePower to call parseCast instead of parseUnary for the base:

func (p *Parser) parsePower() (AstNode, error) {
    base, err := p.parseCast()   // ← was parseUnary
    // ... rest unchanged
}

Task B — AST node and typechecker

Task B1 — ast_nodes.go: add CastExpression 
type CastExpression struct {
    Start, End Position
    Expr       AstNode
    TargetType *TypeExpr
    type_      *Type
}

func (c *CastExpression) SetType(t *Type) { c.type_ = t }
func (c *CastExpression) GetType() *Type  { return c.type_ }
func (c *CastExpression) Range() (Position, Position) {
    return c.Start, c.End
}
Task B2 — typecheck.go: handle CastExpression

In checkExpression, add a case for *script.CastExpression:

case *script.CastExpression:
    // resolve the target type via existing TypeExpr handling
    targetType := c.checkExpression(n.TargetType)
    if targetType == nil {
        return nil
    }

    // type-check the inner expression
    srcType := c.checkStmt(n.Expr)
    if srcType == nil {
        return nil
    }

    // only allow casts between numeric types
    if !isNumeric(srcType) || !isNumeric(targetType) {
        c.error(n, fmt.Errorf(
            "cannot cast %s to %s: only numeric types are castable",
            srcType, targetType,
        ))
        return nil
    }

    n.SetType(targetType)
    return targetType

Add an isNumeric helper (e.g. in helpers.go):

func isNumeric(t *script.Type) bool {
    switch t.Kind {
    case script.TypeKind_I32, script.TypeKind_I64,
         script.TypeKind_F32, script.TypeKind_F64,
         script.TypeKind_Int, script.TypeKind_Float:
        return true
    }
    return false
}

Task C — compiler

Task C — compiler.go: emit conversion instruction

Add a helper that maps (from, to) WAT type strings to a conversion instruction:

func castInstruction(from, to string) string {
    if from == to {
        return ""  // same type, no-op
    }
    key := from + "→" + to
    return map[string]string{
        "i32→i64": "i64.extend_i32_s",
        "i64→i32": "i32.wrap_i64",
        "i32→f32": "f32.convert_i32_s",
        "i32→f64": "f64.convert_i32_s",
        "i64→f32": "f32.convert_i64_s",
        "i64→f64": "f64.convert_i64_s",
        "f32→f64": "f64.promote_f32",
        "f64→f32": "f32.demote_f64",
        "f32→i32": "i32.trunc_f32_s",
        "f32→i64": "i64.trunc_f32_s",
        "f64→i32": "i32.trunc_f64_s",
        "f64→i64": "i64.trunc_f64_s",
    }[key]
}

And the CastExpression compiler case:

case *script.CastExpression:
    if err := c.Compile(n.Expr); err != nil {
        return err
    }

    // normalise: int→i64, float→f64
    from := normaliseWasm(n.Expr.(script.Expression).GetType())
    to   := normaliseWasm(n.GetType())

    instr := castInstruction(from, to)
    if instr != "" {
        c.emit(instr)
    }

Where normaliseWasm maps int→i64, float→f64, and passes i32/i64/f32/f64 through unchanged (you can add this to helpers.go).
