Lesson 59 – The Power Operator (**)

Previous: Lesson 58 – String Indexing

** is already tokenized, parsed, and type-checked. The parser produces a BinaryExpression with Operator: TokenType_Power. What's missing is the binary backend — hitting this case currently falls through to arithOpcode, which returns an error. This lesson adds walkPower.

Why WASM Has No i64.pow

WASM's integer instruction set is minimal: add, sub, mul, div, rem, and bitwise ops. That's it. There is no power instruction for integers — not even in the extended proposals. This isn't an oversight: integer exponentiation is uncommon enough (and easily expressible as a loop) that it didn't make the cut.

Floats do have pow, but it lives in the host environment — you import it from the JS Math object. For now, plex's ** only supports integer operands and we implement it ourselves.

A pattern you'll see repeatedly. When WASM lacks a native instruction, the compiler synthesises the behaviour from the primitives that do exist. Here that means emitting a loop. Other examples already in this compiler: arr.remove, string ==.

The Algorithm: Accumulator Loop

The standard approach for integer power is an accumulator: 

result = 1
while exp > 0 {
    result = result * base
    exp = exp - 1
}
// result = base^original_exp

This runs in O(exp) multiplications. (A faster square-and-halve algorithm exists but adds complexity — the loop is correct and easy to verify.)

Three synthetic locals are needed: base, exp, and result — all i64.

Block-Depth Label Math

The label arithmetic is identical to WhileStatement. After emitting OpBlock and OpLoop:

ActionblockDepthLabel stored
OpBlock; blockDepth++D+1blockLabel = D+1
OpLoop; blockDepth++D+2loopLabel = D+2
br_if to exit block—(D+2)−(D+1) = 1
br to loop top—(D+2)−(D+2) = 0

This is the same formula used in WhileStatement and arr.remove — one pattern for all loops.

Right-Associativity

2 ** 3 ** 2 should parse as 2 ** (3 ** 2) = 2 ** 9 = 512. This is the mathematical convention (and what Python does). Look at ast.go's parsePower: 

func (p *Parser) parsePower() (AstNode, error) {
    base, err := p.parseCast()   // parse the left side first
    if err != nil { return nil, err }

    if p.peek().IsToken() != TokenType_Power {
        return base, nil
    }
    p.advance() // eat **

    exp, err := p.parsePower()   // recurse for the right side — right-assoc
    if err != nil { return nil, err }
    return &BinaryExpression{Left: base, Operator: TokenType_Power, Right: exp}, nil
}

The key: after consuming **, it calls parsePower() recursively instead of parseCast(). That makes it right-recursive, so the right-hand side is parsed first. No codegen change needed — the AST structure itself encodes the correct evaluation order.

Implementation: walkPower

func (b *bodyEncoder) walkPower(n *script.BinaryExpression) error {
    base   := b.addSyntheticLocal(ValI64)
    exp    := b.addSyntheticLocal(ValI64)
    result := b.addSyntheticLocal(ValI64)

    if err := b.walk(n.Left); err != nil { return err }
    b.appendOpCode(OpLocalSet, base)

    if err := b.walk(n.Right); err != nil { return err }
    b.appendOpCode(OpLocalSet, exp)

    // result = 1
    b.buf = append(b.buf, OpI64Const)
    b.buf = AppendSLEB128(b.buf, 1)
    b.appendOpCode(OpLocalSet, result)

    b.buf = append(b.buf, OpBlock, BlockTypeEmpty)
    b.blockDepth++
    blockLabel := uint32(b.blockDepth)

    b.buf = append(b.buf, OpLoop, BlockTypeEmpty)
    b.blockDepth++
    loopLabel := uint32(b.blockDepth)

    // exit when exp <= 0
    b.appendOpCode(OpLocalGet, exp)
    b.buf = append(b.buf, OpI64Const)
    b.buf = AppendSLEB128(b.buf, 0)
    b.buf = append(b.buf, OpI64LeS)
    b.buf = append(b.buf, OpBrIf)
    b.buf = AppendULEB128(b.buf, uint32(b.blockDepth)-blockLabel)

    // result *= base
    b.appendOpCode(OpLocalGet, result)
    b.appendOpCode(OpLocalGet, base)
    b.buf = append(b.buf, OpI64Mul)
    b.appendOpCode(OpLocalSet, result)

    // exp--
    b.appendOpCode(OpLocalGet, exp)
    b.buf = append(b.buf, OpI64Const)
    b.buf = AppendSLEB128(b.buf, 1)
    b.buf = append(b.buf, OpI64Sub)
    b.appendOpCode(OpLocalSet, exp)

    b.buf = append(b.buf, OpBr)
    b.buf = AppendULEB128(b.buf, uint32(b.blockDepth)-loopLabel)

    b.buf = append(b.buf, OpEnd) // end loop
    b.blockDepth--
    b.buf = append(b.buf, OpEnd) // end block
    b.blockDepth--

    b.appendOpCode(OpLocalGet, result)
    return nil
}

Wire it in at the top of the BinaryExpression case, after the &&/|| dispatch: 

if n.Operator == script.TokenType_Power {
    return b.walkPower(n)
}

Comprehension Check

What does x ** 0 return and why?

On entry, result = 1 and exp = 0. The condition (exp <= 0) is immediately true, so br_if fires and the loop body never executes. result is left at 1 — which is the correct mathematical answer for any base to the power 0.

Why does parsePower call itself recursively on the right-hand side instead of calling parseCast?

When parsePower sees a **, it recurses for the exponent. That recursive call will consume b**c before returning, making the whole thing right-associative. If it called parseCast instead, it would only grab b, giving (a**b)**c — left-associative, and the wrong answer mathematically.

The label for br_if (exit the block) is computed as uint32(b.blockDepth) - blockLabel. What does this evaluate to?

blockLabel is captured after OpBlock increments blockDepth (say to D+1). Then OpLoop increments it again to D+2. So uint32(b.blockDepth) - blockLabel = (D+2) - (D+1) = 1. br_if 1 exits the enclosing block. This formula generalises correctly regardless of nesting depth.

Why intercept TokenType_Power before walking left and right (before the type extraction at line 116)?

walkPower calls b.walk(n.Left) and b.walk(n.Right) itself at the right point in the sequence (interleaved with local.set instructions). If the outer BinaryExpression case walked them first, they'd be on the stack with nowhere to store them — and then walkPower would walk them again, evaluating each operand twice.

func TestEndToEnd_Power(t *testing.T) {
    src := `
        export fn square(x: int): int { return x ** 2; }
        export fn cube(x: int): int   { return x ** 3; }
        export fn pow_zero(x: int): int { return x ** 0; }
        export fn right_assoc(): int    { return 2 ** 3 ** 2; }
