Lesson 30 – If Statements & Comparison Operators

Goal: compile if a < b { ... } else { ... } to valid WASM binary. By the end, you can write max(a, b) and see it run through wazero.

Files you'll touch: opcodes.go · body.go · end_to_end_test.go

The Big Idea: Structured Control Flow

In x86 assembly, an if becomes a conditional jump to a label. The CPU can jump anywhere. In WASM, there are no labels, no arbitrary jumps. Instead, control flow is expressed as nested blocks:

if 0x40 ; 0x04 if, 0x40 = "empty" blocktype (no result value) ; ... then branch ... else ; 0x05 — optional ; ... else branch ... end ; 0x0B — closes the if block

The WASM engine validates that every if has a matching end, and that the stack depth is consistent at every branch. This is what lets WASM modules be verified in a single pass — and why WASM is safe to run in a browser sandbox.

Why no labels? Arbitrary jumps are impossible to validate efficiently. Structured nesting is checkable in O(n) with a single stack. This is a deliberate design tradeoff: you lose some flexibility but gain a provably-safe execution model.

Comparisons Always Produce i32

This is the most important thing to internalise before writing any code:

InstructionOperand typesResult type
i64.addi64, i64i64
i64.lt_si64, i64i32
i64.eqi64, i64i32
i32.andi32, i32i32

Arithmetic folds into the same type. Comparison always collapses to i32, where 0 = false and 1 = true. The if instruction pops exactly one i32 from the stack — so comparisons feed directly into it.

This asymmetry is why you need a separate opcode lookup function for comparisons, not just an extension of arithOpcode. The current typechecker sets BinaryExpression.GetType() to the operand type (e.g. i64 for a < b) — which is exactly what you need to pick the right comparison instruction, even though the result is i32.

Blocktype

The byte immediately after the if opcode declares what value (if any) the block leaves on the stack when it exits:

ByteMeaning
0x40Empty — no value pushed. For statement-level ifs.
0x7EReturns i64. For expression-level ifs (both branches must push i64).
0x7FReturns i32.

Plex's IfStatement is statement-only — it never produces a value. So you always emit 0x40.

Byte Layout

For fn max(a: i64, b: i64): i64 { if a > b { return a; } else { return b; } }:

00 ; 0 local groups (no let declarations) 20 00 ; local.get 0 (= a) 20 01 ; local.get 1 (= b) 55 ; i64.gt_s → pushes i32 (1 if a>b, 0 otherwise) 04 40 ; if (empty blocktype) 20 00 ; local.get 0 (= a) 0F ; return 05 ; else 20 01 ; local.get 1 (= b) 0F ; return 0B ; end (closes the if block) 0B ; end (closes the function body)

Implementation

Step 1 — Add opcodes

Open opcodes.go. Add control flow and comparison opcodes:

// Structured control flow
OpIf   byte = 0x04
OpElse byte = 0x05
// OpEnd = 0x0B already exists

BlockTypeEmpty byte = 0x40  // "no result" blocktype for statement-level if

// i64 comparisons — operands are i64, result is always i32
OpI64Eq  byte = 0x51
OpI64Ne  byte = 0x52
OpI64LtS byte = 0x53
OpI64GtS byte = 0x55
OpI64LeS byte = 0x57
OpI64GeS byte = 0x59

// i32 comparisons (used when operands are i32/bool)
OpI32Eq  byte = 0x46
OpI32Ne  byte = 0x47

// i32 logical — used for && and || (booleans are i32)
OpI32And byte = 0x71
OpI32Or  byte = 0x72

Step 2 — Add cmpOpcode() to body.go

Open body.go. Add this alongside arithOpcode. Note how the function takes the operand kind to select the right instruction family, even though all results are i32:

func cmpOpcode(k script.TypeKind, op script.TokenType) (byte, error) {
    switch k {
    case script.TypeKind_I64, script.TypeKind_Int:
        switch op {
        case script.TokenType_EqualEqual:          return OpI64Eq, nil
        case script.TokenType_NotEqual:            return OpI64Ne, nil
        case script.TokenType_LessThen:            return OpI64LtS, nil
        case script.TokenType_GreaterThen:         return OpI64GtS, nil
        case script.TokenType_LessThenOrEqual:     return OpI64LeS, nil
        case script.TokenType_GreaterThenOrEqaul:  return OpI64GeS, nil
        }
    case script.TypeKind_I32:
        switch op {
        case script.TokenType_EqualEqual: return OpI32Eq, nil
        case script.TokenType_NotEqual:   return OpI32Ne, nil
        }
    case script.TypeKind_Bool:
        switch op {
        case script.TokenType_AND: return OpI32And, nil
        case script.TokenType_OR:  return OpI32Or, nil
        }
    }
    return 0, fmt.Errorf("no comparison opcode for %s %v", k, op)
}

Step 3 — Route comparisons in the BinaryExpression case

The current BinaryExpression case always calls arithOpcode. Add a helper and a branch:

func isCmpOp(op script.TokenType) bool {
    switch op {
    case script.TokenType_EqualEqual,
        script.TokenType_NotEqual,
        script.TokenType_LessThen,
        script.TokenType_GreaterThen,
        script.TokenType_LessThenOrEqual,
        script.TokenType_GreaterThenOrEqaul,
        script.TokenType_AND,
        script.TokenType_OR:
        return true
    }
    return false
}

Then update the *script.BinaryExpression case in walk:

case *script.BinaryExpression:
    if err := b.walk(n.Left); err != nil {
        return err
    }
    if err := b.walk(n.Right); err != nil {
        return err
    }
    t := n.GetType()
    if t == nil {
        return fmt.Errorf("no type on binary expression")
    }
    if isCmpOp(n.Operator) {
        op, err := cmpOpcode(t.Kind, n.Operator)
        if err != nil { return err }
        b.buf = append(b.buf, op)
        return nil
    }
    op, err := arithOpcode(t.Kind, n.Operator)
    if err != nil { return err }
    b.buf = append(b.buf, op)
    return nil

Step 4 — Handle *BooleanLiteral

Booleans are i32 in WASM. true → 1, false → 0. Add the case to walk:

case *script.BooleanLiteral:
    b.buf = append(b.buf, OpI32Const)
    if n.Value {
        b.buf = AppendSLEB128(b.buf, 1)
    } else {
        b.buf = AppendSLEB128(b.buf, 0)
    }
    return nil

Step 5 — Handle *IfStatement

This is the core of the lesson. The pattern is: emit condition → emit if 0x40 → emit then body → optionally emit else + else body → emit end:

case *script.IfStatement:
    if err := b.walk(n.Condition); err != nil {
        return err
    }
    b.buf = append(b.buf, OpIf, BlockTypeEmpty)
    if err := b.walk(n.Body); err != nil {
        return err
    }
    if n.Else != nil {
        b.buf = append(b.buf, OpElse)
        if err := b.walk(n.Else); err != nil {
            return err
        }
    }
    b.buf = append(b.buf, OpEnd)
    return nil
Notice: walk is recursive — n.Body is a *script.Block, which the existing Block case handles. The if/else/end framing is entirely in this new case; the body contents are handled by the same switch.

Step 6 — Write the test

Add to end_to_end_test.go. max exercises both branches of if/else and requires a working comparison:

func TestEndToEnd_IfElse(t *testing.T) {
    src := `
        fn max(a: i64, b: i64): i64 {
            if a > b {
                return a;
            } else {
                return b;
            }
        }
    `
    runOne(t, src, "max", []uint64{42, 17}, 42)  // takes then branch
    runOne(t, src, "max", []uint64{17, 42}, 42)  // takes else branch
}

Note: runOne creates a fresh wazero runtime each call, so two calls with different args correctly test both branches. Run with:

go test ./compiler/binary/... -run TestEndToEnd -v

What's Next

  • While loops — WASM's block + loop + br/br_if pattern. More complex than if because WASM loops branch backward to the loop top, not forward.
