Lesson 43 – Bounds Checks and the Unreachable Trap

Goal: make arr[100] on a 3-element array trap instead of reading garbage. One new opcode you've technically used since lesson 28 (unreachable) finally earns its keep. Same shape for reads and writes.

Files you'll touch: body.go · end_to_end_test.go

The Safety Gap WASM Won't Close For You

WASM gives you a lot of static safety for free. Stack types are checked. Function-call signatures are checked. Block-result types are checked. But memory addresses are checked only at the page-coarseness: if you load from an address inside your allocated memory, the engine doesn't care whether that address is "inside an array" or "between two arrays" — they're all just bytes.

This means today's arr[100] on a 3-element i64 array at offset 0:

  1. Computes 100 * 8 = 800 — the offset from the array's body.
  2. Adds 4 (via memarg) — final address 804.
  3. Loads 8 bytes at address 804. Memory is zero-initialised but writable; the load returns whatever happens to be there — likely zero in this case, but completely undefined in general.
This isn't an unsafe-language confession. Every systems language emits the same shape of bytecode at this layer. C would do exactly this. Safer languages — Rust, Go, Java, plex-after-this-lesson — emit a comparison and conditional trap before the load. The check costs three instructions and shifts the failure mode from "silent garbage" to "loud crash". That's the trade.

The Unreachable Trap

OpcodeByteBehaviour
unreachable0x00Traps unconditionally at runtime — wazero surfaces this as an error from Call.

You've been emitting OpUnreachable since lesson 28 as a defensive byte after each function's return (section.go:69). Today is the first time it appears in live code paths — reachable when a check fails.

Why unreachable instead of a smarter "throw"? WASM has no built-in exception mechanism (well, there's a proposal-stage Exception Handling feature, but it's not in our toolchain). unreachable is the universal "this should never execute; abort the module" signal. Hosts (wazero, browsers, the spec) all agree on what it means: trap with no payload. That's enough to fail loudly; richer error reporting needs a host call, which plex doesn't have yet.

The Bounds-Check Sequence

The check happens after we've computed the wrapped i32 index, before we use it. We need two values:

  • The wrapped index i (i32).
  • The array's length (i32), loaded via i32.load offset=0 at the base pointer.

Both need to be live at the comparison and still usable for the load/store that follows. The cleanest way is to stash the base and index in synthetic locals once and reload them as needed — same allocator-tmp pattern lesson 40 used.

; save base and idx into synthetic locals walk(target) ; [base] local.set arrBase ; [] walk(index) ; [idx_i64] i32.wrap_i64 ; [idx_i32] local.set arrIdx ; [] ; bounds: trap if idx >= len local.get arrIdx ; [idx] local.get arrBase ; [idx, base] i32.load align=2 offset=0 ; [idx, len] i32.ge_u ; [idx >= len ? 1 : 0] if BlockTypeEmpty unreachable end ; [] ; address = base + idx*sz, then load/store at offset=4 local.get arrBase local.get arrIdx i32.const elemSize i32.mul i32.add typed.load align=N offset=4 ; (or typed.store after pushing value)
Unsigned compare catches negative indices for free. i32.wrap_i64 keeps only the low 32 bits. If the user passed a negative i64 (e.g. -1), wrap yields 0xFFFFFFFF — read as unsigned, that's the maximum u32. It's always > any reasonable array length, so the bounds check trips and the program traps. One comparison covers both "too big" and "negative". This is a standard trick in bounds-checked languages.

Implementation

The shape repeats almost verbatim across ArrayAccess and ArrayAssignment. Two reasonable strategies:

  • Inline both. Copy the 9-instruction prologue into each case. More bytes, no abstraction, easy to delete one if needed.
  • Factor a helper. Write one method on bodyEncoder that emits the prologue and returns the two synthetic-local indices. Less duplication, but introduces a new helper for a single use-pair.

For one extra call site, inline is cleaner. When the third indexed-load shape arrives (slices? string byte-at? structs with computed offsets?), refactor then. Today, copy.

Step 1 — Refactor *script.ArrayAccess

The current case in body.go does the read in a single straight-line sequence. Replace it with the bounds-check-then-read shape:

case *script.ArrayAccess:
    elemType := n.GetType()
    if elemType == nil {
        return fmt.Errorf("array access has no element type")
    }
    elemSize := elemSizeOf(elemType.Kind)
    loadOp, loadAlign := loadOpcode(elemType.Kind)

    arrBase := b.addSyntheticLocal(ValI32)
    arrIdx := b.addSyntheticLocal(ValI32)

    // stash base and wrapped idx
    if err := b.walk(n.Target); err != nil { return err }
    b.buf = append(b.buf, OpLocalSet); b.buf = AppendULEB128(b.buf, arrBase)
    if err := b.walk(n.Index); err != nil { return err }
    b.buf = append(b.buf, OpI32WrapI64)
    b.buf = append(b.buf, OpLocalSet); b.buf = AppendULEB128(b.buf, arrIdx)

    // bounds: trap if idx >= len
    b.buf = append(b.buf, OpLocalGet); b.buf = AppendULEB128(b.buf, arrIdx)
    b.buf = append(b.buf, OpLocalGet); b.buf = AppendULEB128(b.buf, arrBase)
    b.buf = append(b.buf, OpI32Load); b.buf = AppendULEB128(b.buf, 2); b.buf = AppendULEB128(b.buf, 0)
    b.buf = append(b.buf, OpI32GeU)
    b.buf = append(b.buf, OpIf, BlockTypeEmpty)
    b.blockDepth++
    b.buf = append(b.buf, OpUnreachable)
    b.buf = append(b.buf, OpEnd)
    b.blockDepth--

    // address: base + idx*elemSize
    b.buf = append(b.buf, OpLocalGet); b.buf = AppendULEB128(b.buf, arrBase)
    b.buf = append(b.buf, OpLocalGet); b.buf = AppendULEB128(b.buf, arrIdx)
    b.buf = append(b.buf, OpI32Const); b.buf = AppendSLEB128(b.buf, int64(elemSize))
    b.buf = append(b.buf, OpI32Mul)
    b.buf = append(b.buf, OpI32Add)

    // load at +4
    b.buf = append(b.buf, loadOp)
    b.buf = AppendULEB128(b.buf, loadAlign)
    b.buf = AppendULEB128(b.buf, 4)
    return nil

You'll need OpI32GeU = 0x4F in opcodes.go — add it next to the existing i32 comparison ops:

OpI32GeS byte = 0x4E
OpI32GeU byte = 0x4F

Step 2 — Mirror in *script.ArrayAssignment

Same bounds-check prologue, same locals, same comparison. The difference: walk the value between the address arithmetic and the store, and emit storeOp at the end:

case *script.ArrayAssignment:
    elemType := n.Target.GetType()
    elemSize := elemSizeOf(elemType.Kind)
    storeOp, storeAlign := storeOpcode(elemType.Kind)

    arrBase := b.addSyntheticLocal(ValI32)
    arrIdx := b.addSyntheticLocal(ValI32)

    // stash base and wrapped idx — same as ArrayAccess
    if err := b.walk(n.Target.Target); err != nil { return err }
    b.buf = append(b.buf, OpLocalSet); b.buf = AppendULEB128(b.buf, arrBase)
    if err := b.walk(n.Target.Index); err != nil { return err }
    b.buf = append(b.buf, OpI32WrapI64)
    b.buf = append(b.buf, OpLocalSet); b.buf = AppendULEB128(b.buf, arrIdx)

    // bounds check — same as ArrayAccess
    b.buf = append(b.buf, OpLocalGet); b.buf = AppendULEB128(b.buf, arrIdx)
    b.buf = append(b.buf, OpLocalGet); b.buf = AppendULEB128(b.buf, arrBase)
    b.buf = append(b.buf, OpI32Load); b.buf = AppendULEB128(b.buf, 2); b.buf = AppendULEB128(b.buf, 0)
    b.buf = append(b.buf, OpI32GeU)
    b.buf = append(b.buf, OpIf, BlockTypeEmpty)
    b.blockDepth++
    b.buf = append(b.buf, OpUnreachable)
    b.buf = append(b.buf, OpEnd)
    b.blockDepth--

    // address = base + idx*elemSize
    b.buf = append(b.buf, OpLocalGet); b.buf = AppendULEB128(b.buf, arrBase)
    b.buf = append(b.buf, OpLocalGet); b.buf = AppendULEB128(b.buf, arrIdx)
    b.buf = append(b.buf, OpI32Const); b.buf = AppendSLEB128(b.buf, int64(elemSize))
    b.buf = append(b.buf, OpI32Mul)
    b.buf = append(b.buf, OpI32Add)

    // push value, then store at +4
    if err := b.walk(n.Value); err != nil { return err }
    b.buf = append(b.buf, storeOp)
    b.buf = AppendULEB128(b.buf, storeAlign)
    b.buf = AppendULEB128(b.buf, 4)
    return nil
The duplication is real but bounded. Roughly twelve lines of bounds-check shared between the two arms. When the third indexed-access site arrives (likely struct field access with a runtime offset, or string byte-at), pull the prologue into a helper. Premature factoring at two call sites tends to hurt readability more than it helps; at three it pays off.

Step 3 — Tests

Two new tests: one verifies in-bounds still works (regression guard), one verifies out-of-bounds traps with a wazero error:

func TestEndToEnd_BoundsInBounds(t *testing.T) {
    src := `
        fn get_at(): int {
            let arr = [10, 20, 30];
            return arr[2];
        }
        fn set_at(): int {
            let arr = [10, 20, 30];
            arr[0] = 99;
            return arr[0];
        }
    `
    runOne(t, src, "get_at", nil, 30)
    runOne(t, src, "set_at", nil, 99)
}

func TestEndToEnd_BoundsOutOfRange(t *testing.T) {
    src := `
        fn read_oob(): int {
            let arr = [10, 20, 30];
            return arr[100];
        }
        fn write_oob(): int {
            let arr = [10, 20, 30];
            arr[100] = 99;
            return 0;
        }
    `
    ast, err := script.Parse(strings.NewReader(src))
    if err != nil { t.Fatal(err) }
    wasm, err := binary_wasm.CompileProgram(ast)
    if err != nil { t.Fatal(err) }

    ctx := t.Context()
    r := wazero.NewRuntime(ctx)
    defer r.Close(ctx)
    mod, err := r.Instantiate(ctx, wasm)
    if err != nil { t.Fatalf("instantiate: %v", err) }

    _, err = mod.ExportedFunction("read_oob").Call(ctx)
    if err == nil {
        t.Fatalf("expected a trap on out-of-bounds read; got nil error")
    }

    _, err = mod.ExportedFunction("write_oob").Call(ctx)
    if err == nil {
        t.Fatalf("expected a trap on out-of-bounds write; got nil error")
    }
}

Run:

go test ./internal/script/compiler/binary/... -v

The error wazero returns from a tripped unreachable contains the word "unreachable" — the test just asserts err != nil so the exact message format can change without breaking it.

The Cost — and Where It Goes

You added roughly nine instructions per array access: two saves, two loads, one length-load, one compare, an if-end pair, the unreachable, plus the locals you didn't have before. For an array access inside a tight loop, that's a real overhead.

Real-world compilers earn this back via hoisting. Walk the loop. The array's length doesn't change. The check idx < len reduces to "does the loop's index ever exceed len?", which the compiler can prove statically for many shapes (for i in 0..len, while i < arr.len()). Once proven, the check is removed entirely. Bounds-check elimination (BCE) is a small but mature optimisation; Rust's iter(), Java's System.arraycopy, .NET's Span<T> all rely on it. Plex doesn't have BCE — yet — but the shape of the code you emit today is what a BCE pass would later eat.

What's Next

  • Struct literals and field access. Multi-stage shape similar to lesson 42 — new AST node, parser hook, typechecker arm, codegen case. The new wrinkle: a per-struct field-offset table built by the compiler from the struct declaration, used at every obj.field codegen site.
  • String byte-at indexing. Currently the typechecker reports s[i] as string, which is awkward. Resolving the semantics (return a byte? a one-char substring?) is a typechecker decision before any codegen.
  • Factor the bounds-check prologue. The third indexed site will trigger this. Reasonable shape: (b *bodyEncoder).emitBoundsCheckedAddress(target, index AstNode, elemSize uint32) error that emits everything through the i32.add and leaves the address on the stack.
