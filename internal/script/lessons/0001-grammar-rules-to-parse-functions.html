Grammar Rules → Parse Functions

The single idea that makes recursive descent work

The Big Idea

Recursive descent parsing has one core mechanic. Once you see it, every parser makes sense:

The Core Insight
Every grammar rule becomes a function. Every function returns an AST node. The parser is just these functions calling each other — often recursively, hence the name.

Your tokenizer already broke source text into a flat list of tokens. The parser's job is to give that list structure — to discover that fn starts a function, that {...} forms a block, that 1 + 2 * 3 has a specific nesting. The grammar is the map; the parse functions are the territory.

Grammar Notation (BNF)

Grammars are usually written in BNF or a variant. Here's what the notation means:

rule ::= part | "literal"
( ... )?   optional
( ... )*   zero or more
( ... )+   one or more
|            alternatives

Here's a tiny grammar for a plex expression that only handles literals and additions:

expression ::= term ( "+" term )*
term       ::= NUMBER | IDENT | "(" expression ")"

Two grammar rules → two Go functions. That's the whole translation.

The Parser Skeleton

Before writing the rules, we need a parser struct that holds the token list and a cursor telling us where we are:

type Parser struct {
    tokens []Token
    pos    int
}

// peek at the current token without consuming it
func (p *Parser) peek() Token {
    if p.pos >= len(p.tokens) {
        return NewDataToken(TokenType_EOF, Position{}, Position{})
    }
    return p.tokens[p.pos]
}

// consume the current token and advance
func (p *Parser) advance() Token {
    t := p.peek()
    p.pos++
    return t
}

// advance only if the current token matches; error otherwise
func (p *Parser) expect(tt TokenType) (Token, error) {
    if p.peek().IsToken() != tt {
        return nil, fmt.Errorf("expected %v, got %v", tt, p.peek().IsToken())
    }
    return p.advance(), nil
}
Why peek + advance?
Recursive descent needs one token of lookahead — you look at the next token to decide which rule to apply, then consume it. This pattern (peek to decide, advance to consume) is the heartbeat of every recursive descent parser. See Crafting Interpreters §6.

Grammar Rules Become Functions

Now translate the grammar literally. Each rule is a Go function that returns (AstNode, error):

// expression ::= term ( "+" term )*
func (p *Parser) parseExpression() (AstNode, error) {
    left, err := p.parseTerm()
    if err != nil {
        return nil, err
    }

    for p.peek().IsToken() == TokenType_Plus {
        op := p.advance()  // consume the "+"
        right, err := p.parseTerm()
        if err != nil {
            return nil, err
        }
        start, _ := left.Range()
        _, end := right.Range()
        left = &BinaryExpression{
            Start:    start,
            End:      end,
            Left:     left,
            Right:    right,
            Operator: op.(*ValueToken).Value,
        }
    }

    return left, nil
}

// term ::= NUMBER | IDENT | "(" expression ")"
func (p *Parser) parseTerm() (AstNode, error) {
    t := p.peek()
    switch t.IsToken() {

    case TokenType_Number:
        tok := p.advance().(*ValueToken)
        return &NumberLiteral{Start: tok.Start, End: tok.End, Value: tok.Value}, nil

    case TokenType_Ident:
        tok := p.advance().(*ValueToken)
        return &Identifier{Start: tok.Start, End: tok.End, Name: tok.Value}, nil

    case TokenType_BracketParamOpen:  // "("
        p.advance()  // consume "("
        inner, err := p.parseExpression()  // recurse!
        if err != nil {
            return nil, err
        }
        _, err = p.expect(TokenType_BracketParamClose)  // consume ")"
        return inner, err

    default:
        return nil, fmt.Errorf("unexpected token: %v", t.IsToken())
    }
}
See the recursion?
parseTerm handles "(" expression ")" by calling parseExpression — which will call parseTerm again. This is how arbitrarily deep nesting (((1 + 2))) gets handled with no special code. The call stack is the nesting.

What AST Nodes Are Missing

The code above references two node types not yet in ast_nodes.go. You'll need to add them:

type NumberLiteral struct {
    Start, End Position
    Value      string  // raw text; convert to float64 at eval time
}
func (n *NumberLiteral) Range() (Position, Position) { return n.Start, n.End }

type Identifier struct {
    Start, End Position
    Name       string
}
func (i *Identifier) Range() (Position, Position) { return i.Start, i.End }
Heads up: BinaryExpression is missing Range()
The existing BinaryExpression in ast_nodes.go doesn't implement the AstNode interface yet — it's missing the Range() method. Add it before compiling.
