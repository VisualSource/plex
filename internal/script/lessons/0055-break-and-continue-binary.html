Lesson 55 – Break and Continue in the Binary Backend

Previous: Lesson 54 – String Equality

Break and continue are implemented in body.go and have been there since the while-loop lesson — but they have no end-to-end tests. This lesson digs into why the implementation works (the depth math is subtle when break appears inside a nested if), then confirms it by writing the missing tests.

The Core Problem: WASM Has No Goto

Every imperative language has break and continue. In most compilers they map trivially to a jmp instruction. WASM has no jmp. Its control flow is structured: you can only branch outward from a named construct, and the construct must have been syntactically opened in the enclosing code.

The three structured control constructs:

ConstructOpcodeWhat br n does here
block0x02jumps past its end (forward exit)
loop0x03jumps to its beginning (backward, i.e. loop again)
if0x04jumps past its end (forward exit)

br n targets the n-th enclosing construct, counting from 0 (innermost). So br 0 from inside a loop goes back to the top of the loop. br 1 from inside a loop that is itself inside a block exits the block.

How While Loops Are Compiled

A while becomes a block wrapping a loop. The block is the break target; the loop is the continue target.

block depth after = D+1 ← blockLabel loop depth after = D+2 ← loopLabel <condition> i32.eqz br_if ? ; exits block when condition is false <body> br ? ; goes back to top of loop (continue loop) end depth after = D+1 end depth after = D

In body.go, the WhileStatement case:

b.buf = append(b.buf, OpBlock, BlockTypeEmpty)
b.blockDepth++
blockLabel := uint32(b.blockDepth)  // absolute depth of the BLOCK

b.buf = append(b.buf, OpLoop, BlockTypeEmpty)
b.blockDepth++
loopLabel := uint32(b.blockDepth)   // absolute depth of the LOOP

b.loopStack = append(b.loopStack, loopEntry{blockLabel, loopLabel})

Then at the end of the body, the backward branch is:

b.buf = append(b.buf, OpBr)
b.buf = AppendULEB128(b.buf, uint32(b.blockDepth)-loopLabel)
// = D+2 - (D+2) = 0  → br 0 → top of loop ✓

Break: Exiting the Block

case *script.BreakStatement:
    entry := b.loopStack[len(b.loopStack)-1]
    b.buf = append(b.buf, OpBr)
    b.buf = AppendULEB128(b.buf, uint32(b.blockDepth)-entry.blockLabel)

At the top level of the while body, b.blockDepth == loopLabel == blockLabel+1, so:

blockDepth - blockLabel = (D+2) - (D+1) = 1 → br 1 exits the outer block. ✓

The Nested Case: Break Inside an If

This is where the depth math earns its keep. When break appears inside an if inside a while, entering that if added 1 to blockDepth:

block D+1 = blockLabel loop D+2 = loopLabel ... if D+3 ← b.blockDepth when break emits break ; br (D+3) - (D+1) = 2 end ... end end

br 2 from inside the if: br 0 = top of if, br 1 = top of loop, br 2 = exit block. That is exactly break. The formula currentDepth - blockLabel automatically produces the right relative depth regardless of how many extra ifs are nested.

Key insight. blockLabel and loopLabel are absolute depths recorded at compile time. b.blockDepth at the point a branch is emitted is the current absolute depth. Their difference is the relative WASM branch depth. This works at any nesting level without any special-casing.

Continue: Jumping Back to the Loop

Continue uses loopLabel instead of blockLabel: 

case *script.ContinueStatement:
    entry := b.loopStack[len(b.loopStack)-1]
    b.buf = append(b.buf, OpBr)
    b.buf = AppendULEB128(b.buf, uint32(b.blockDepth)-entry.loopLabel)

From inside an if at depth D+3:

(D+3) - (D+2) = 1 → br 1 exits the if and goes back to the top of the loop. ✓

From outside the if at depth D+2: (D+2) - (D+2) = 0 → br 0 stays in the loop. ✓

Modulo: Already Wired Up

The standard continue example uses % (modulo). In opcodes.go, arithOpcode already handles it:

TypeOperatorOpcodeHex
i64%i64.rem_s0x81
i32%i32.rem_s0x6F

rem_s = signed remainder. Like C's %, it returns negative results for negative dividends. No new code needed — modulo works today.

Depth Check

A while loop starts at blockDepth = 0. After emitting the outer block and inner loop, what is blockDepth?

blockDepth increments once for block (→1) and once for loop (→2).

blockLabel = 1, loopLabel = 2. Break is inside two nested ifs inside the while body. What br depth does break emit?

Two nested ifs push blockDepth to 2+2=4. blockDepth - blockLabel = 4 - 1 = 3.

continue appears at the top level of a while body (no extra nesting). What does the br depth compute to?

blockDepth = loopLabel at the top of the body. loopLabel - loopLabel = 0. br 0 loops back.

What does br 0 do inside a loop construct?

For loops, br 0 jumps to the beginning. For blocks and ifs, br 0 exits to after the end. The construct type determines the direction.

Your Task: Write the Missing Tests

Add these two test functions to end_to_end_test.go.

TestEndToEnd_Break

Search an array and stop at the first element greater than 25:

export fn find_first(): int {
    let arr = [10, 20, 30, 40, 50];
    let i: int = 0;
    let found: int = -1;
    while i < arr.len() {
        if arr[i] > 25 {
            found = arr[i];
            break;
        }
        i = i + 1;
    }
    return found;
}

Expected: 30 (stops at the first element > 25, skipping 40 and 50).

Add a second sub-case: an array where no element matches, so the loop runs to completion. Expected: -1.

TestEndToEnd_Continue

Sum only the even numbers from 1 to n using continue to skip odds:

export fn sum_evens(n: i64): i64 {
    let i: i64 = 0;
    let sum: i64 = 0;
    while i < n {
        i = i + 1;
        if (i % 2) != 0 {
            continue;
        }
        sum = sum + i;
    }
    return sum;
}

Expected: sum_evens(10) = 30 (2+4+6+8+10).

Steps
  1. Add both test functions to end_to_end_test.go.
  2. Run go test ./internal/script/compiler/binary/... -run TestEndToEnd_Break
  3. Run go test ./internal/script/compiler/binary/... -run TestEndToEnd_Continue
  4. If either fails: check whether blockDepth is correctly balanced at every point that emits a branch. The tool is tracing the absolute depth at each opcode emission.
Watch for blockDepth imbalance. If the depth is wrong at the point break/continue emits, the computed relative branch depth will be wrong. The symptom is usually an unexpected result rather than a validation error — the branch jumps to the wrong target silently. Print b.blockDepth at the emission site if results are off.

Why This Matters

The loopStack pattern is a general technique for compiling any structured jump in SSA-less backends. Every compiler that targets a structured control flow IR (WASM, JVM bytecode, CLR CIL) uses some variant of it. The key invariant is: labels are absolute; branches are relative; the difference is always correct.
