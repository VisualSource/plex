Lesson 29 – Locals via let

Goal: compile let x: i64 = a + b; to valid WASM binary. By the end of this lesson, let declarations will work end-to-end through wazero.

Files you'll touch: opcodes.go · body.go · section.go · end_to_end_test.go

What's Broken Right Now

Two independent gaps prevent let from working:

  1. walk() has no case for *script.VariableDeclaration — any let statement falls through to return fmt.Errorf("unhandled AST node %T").
  2. encodeCodeEntry hardcodes 0 for the locals vec — even if we emitted local.set, the WASM engine would reject the module because the local index doesn't exist.

Fix both and let works. This lesson shows you how, and why the fix isn't as simple as just adding a case to the switch.

The WASM Code Entry Format

The binary format for a code entry (spec §5.5.10) is:

code_entry  = size:u32  code
code        = locals:vec(local_group)  expr  end
local_group = count:u32  type:valtype

A local_group is a run-length-encoded batch: count locals all of the same type. For example, [{2, i64}, {1, i32}] declares two i64 locals followed by one i32 local. The total number of locals declared is sum(count).

Critical constraint: the locals vec appears at the top of the code body, before any bytecode. The engine parses it once, allocates space for all locals, then executes the bytecode. There is no inline local.declare instruction.

Index space

Params and locals share a single flat index space:

SlotWho owns it
0..n-1Function parameters (in declaration order)
n..n+k-1let-declared locals (in order of first appearance)

The bodyEncoder already assigns params in newBodyEncoder. Locals will continue from where params left off — len(b.locals) at the moment a VariableDeclaration is first seen is exactly the right next index.

The Two-Phase Problem

Here's the fundamental tension:

  • The locals vec must be written first — before any bytecode.
  • But let declarations can appear anywhere inside the function body.

You can't know what locals to declare until you've walked the body. But you can't start walking the body (for bytecode) until you've written the locals declaration. The solution is two passes:

Pass 1 — Collect scan
Walk the AST to find every VariableDeclaration. Assign each a local index (continuing from after params). Record its WASM valtype. No bytecode is emitted yet.
Pass 2 — Emit walk
Walk the AST again to emit bytecode. VariableDeclaration emits local.set; Identifier emits local.get — both using the indices assigned in Pass 1.
Compiler theory note: this two-phase pattern is everywhere. Hoisting in JavaScript, forward declarations in C, function-body pre-scanning in many bytecode VMs — all solve the same problem: the output format has ordering constraints the AST doesn't share.

Implementation

Step 0 — Fix a latent bug first Open opcodes.go. Notice that both OpI64Mul and OpI64DivS are declared as 0x7F. This means any i64 multiplication silently emits the division opcode — a silent correctness bug with no test to catch it yet. Fix: OpI64Mul should be 0x7E.

After the fix, the relevant i64 opcodes are:

// i64 arithmetic — from the WASM binary spec §5.4.1
OpI64Add  byte = 0x7C
OpI64Sub  byte = 0x7D
OpI64Mul  byte = 0x7E  // was 0x7F — now correct
OpI64DivS byte = 0x7F
OpI64RemS byte = 0x81

Step 1 — Add OpLocalSet

Still in opcodes.go, add the missing opcode alongside OpLocalGet:

OpLocalGet byte = 0x20
OpLocalSet byte = 0x21

(local.tee = 0x22 pushes and sets — useful later for expressions like x = x + 1 in a larger expression context, but not needed today.)

Step 2 — Extend bodyEncoder with a localTypes slice

Open body.go. The struct currently holds only the index map. Add a field to track the WASM valtype for each let-declared local (in order):

type bodyEncoder struct {
    buf        []byte
    locals     map[string]uint32
    localTypes []byte   // WASM valtype for each let local, in order
}

Step 3 — Write collectLocals (Pass 1)

Add this method to bodyEncoder. It walks the AST looking only for VariableDeclaration nodes. It does not emit any bytecode.

func (b *bodyEncoder) collectLocals(node script.AstNode) {
    switch n := node.(type) {
    case *script.Block:
        for _, s := range n.Stmts {
            b.collectLocals(s)
        }
    case *script.VariableDeclaration:
        b.locals[n.Name] = uint32(len(b.locals))
        t := n.GetType()
        if t != nil {
            b.localTypes = append(b.localTypes, valType(t))
        } else {
            b.localTypes = append(b.localTypes, ValI64)
        }
    }
}
Why len(b.locals)? Params are already in the map. If a function has 2 params (indices 0 and 1), len(b.locals) == 2 when the first let is encountered — so the first local gets index 2. Each subsequent declaration advances the count naturally.

Step 4 — Call collectLocals in newBodyEncoder

After registering params, run the pre-scan:

func newBodyEncoder(f *script.FunctionDeclaration, sig funcSig) *bodyEncoder {
    b := &bodyEncoder{locals: make(map[string]uint32)}
    var idx uint32
    if sig.isMethod {
        b.locals["self"] = idx
        idx++
    }
    for _, p := range f.Params {
        b.locals[p.Name] = idx
        idx++
    }
    b.collectLocals(f.Body)  // pre-scan: assign indices to all let declarations
    return b
}

Step 5 — Encode the real locals vec in encodeCodeEntry

Open section.go. Replace the hardcoded 0 with the actual locals declaration. Use the simple form — one group per local — which the spec allows even if it's not maximally compact:

func encodeCodeEntry(f *script.FunctionDeclaration, sig funcSig) ([]byte, error) {
    var body []byte

    enc := newBodyEncoder(f, sig)

    // Locals vec: one group per local (count=1, valtype)
    body = AppendULEB128(body, uint32(len(enc.localTypes)))
    for _, vt := range enc.localTypes {
        body = AppendULEB128(body, 1)
        body = append(body, vt)
    }

    if err := enc.walk(f.Body); err != nil {
        return nil, err
    }

    body = append(body, enc.buf...)
    body = append(body, OpEnd)

    var entry []byte
    entry = AppendULEB128(entry, uint32(len(body)))
    entry = append(entry, body...)
    return entry, nil
}

The old hardcoded line — body = AppendULEB128(body, 0) — is gone. The count is now len(enc.localTypes), and each type is emitted as its own group of 1.

Step 6 — Handle *VariableDeclaration in walk (Pass 2)

Back in body.go, add the missing case. The index was already assigned in Pass 1 — just look it up:

case *script.VariableDeclaration:
    if n.Init != nil {
        if err := b.walk(n.Init); err != nil {
            return err
        }
    }
    idx := b.locals[n.Name]  // assigned in collectLocals
    b.buf = append(b.buf, OpLocalSet)
    b.buf = AppendULEB128(b.buf, idx)
    return nil
Stack discipline: walk(n.Init) pushes the computed value onto the WASM stack. local.set pops that value and stores it in the local slot. The net effect on the stack is zero — which is correct for a statement.

Step 7 — Handle *AssignmentExpression in walk (bonus)

While you're here, also handle re-assignment (x = x + 1) so the switch doesn't reject it later:

case *script.AssignmentExpression:
    if err := b.walk(n.Value); err != nil {
        return err
    }
    idx, ok := b.locals[n.Name]
    if !ok {
        return fmt.Errorf("unknown local %s", n.Name)
    }
    b.buf = append(b.buf, OpLocalSet)
    b.buf = AppendULEB128(b.buf, idx)
    return nil

Step 8 — Write the test

Add to end_to_end_test.go. This test chains two let bindings to verify both locals get distinct indices and both values are live at the same time:

func TestEndToEnd_Locals(t *testing.T) {
    src := `
        fn accumulate(a: i64, b: i64): i64 {
            let x: i64 = a + b;
            let y: i64 = x + 1;
            return y;
        }
    `
    runOne(t, src, "accumulate", []uint64{20, 21}, 42)
}

Run with: go test ./compiler/binary/... -run TestEndToEnd -v
