Lesson 54 – String Equality

Previous: Lesson 53 – String Concatenation

With + on strings working, the next gap is == and !=. Comparing two i32 pointers for equality only tells you whether they point to the same allocation — not whether the strings contain the same text. A real equality check requires reading the actual bytes, and WASM has no bulk-compare instruction. This lesson compiles it to a loop.

The Current Error

export fn is_hello(s: string): bool {
    return s == "hello";
}

Compiler output today: no comparison opcode for string ==. The cmpOpcode function in opcodes.go has no case for TypeKind_String — and correctly so, since there is no native opcode. You add a type-directed early exit in BinaryExpression, just like you did for +.

The New Instruction: i32.load8_u

Comparing strings byte-by-byte requires loading single bytes from memory. i32.load8_u (opcode 0x2D) loads one byte and zero-extends it to i32. Add it to opcodes.go: 

OpI32Load8U byte = 0x2D   // load 1 byte, zero-extend to i32

Like all load instructions, it takes two LEB128 immediates: alignment (use 0 for single bytes — no alignment requirement) and offset (use 0).

The Algorithm

Two phases:

  1. Fast path — if the lengths differ, the strings cannot be equal. Skip the byte loop entirely.
  2. Byte loop — walk both strings simultaneously, exiting immediately if any byte differs.

Six synthetic locals:

LocalTypeHolds
leftPtri32pointer to left string
rightPtri32pointer to right string
leftLeni32byte count of left string
rightLeni32byte count of right string
cursori32current byte index (0 to leftLen−1)
isEquali321 if equal so far, 0 if mismatch found

Control Flow Structure

The key shape is one outer block (used as a multi-exit point) enclosing one loop and one nested if. The branch depths from each exit point are fixed:

; D = b.blockDepth before walkStringEq is entered i32.const 1 / local.set isEqual ; assume equal ; read leftLen, rightLen, set cursor = 0 BLOCK depth D+1 local.get leftLen / local.get rightLen i32.ne IF depth D+2 i32.const 0 / local.set isEqual ; lengths differ → not equal br 1 ────────────────────────────────► exit BLOCK END depth D+1 LOOP depth D+2 local.get cursor / local.get leftLen i32.ge_u br_if 1 ────────────────────────────────► exit BLOCK (done, isEqual=1) ; load left[cursor] and right[cursor] i32.ne IF depth D+3 i32.const 0 / local.set isEqual ; bytes differ br 2 ────────────────────────────────► exit BLOCK (isEqual=0) END depth D+2 ; cursor++ br 0 ────────────────────────────────► continue LOOP END depth D+1 END depth D local.get isEqual ; result: 0 or 1 ; for !=: append i32.eqz
Branch depth rules: from inside a loop, br 0 targets the loop itself (continues it). From inside the nested if at depth D+3, br 2 skips over 2 enclosing constructs (the if at D+3 → loop at D+2 → block at D+1) and exits the block. The outer block is the common "done" target for all early exits.
blockDepth discipline (review from lesson 50): the internal block and loop are not pushed onto loopStack (user break/continue must not reach them), but b.blockDepth must still be incremented and decremented correctly. User-visible while loops store their break/continue targets as absolute depth values; an unbalanced internal depth would corrupt those calculations if this expression appears inside a loop.

The byte-load sequence

Loading string[cursor] from a string at ptr:

; address = ptr + 4 + cursor
20 ptr     ; local.get ptr
41 04      ; i32.const 4
6A         ; i32.add
20 cursor  ; local.get cursor
6A         ; i32.add
2D 00 00   ; i32.load8_u align=0 offset=0

Do this twice (once for leftPtr, once for rightPtr), then i32.ne to check for a mismatch.

Wiring into BinaryExpression

In body.go, add a second early exit alongside the + check:

if opType.Kind == script.TypeKind_String {
    switch n.Operator {
    case script.TokenType_Plus:
        return b.walkStringConcat(n)
    case script.TokenType_EqualEqual, script.TokenType_NotEqual:
        return b.walkStringEq(n)
    }
}

walkStringEq checks n.Operator at the end: emit i32.eqz for !=, nothing extra for ==.

Implementation Task

Task — add string equality to the binary backend

Step 1. Add OpI32Load8U byte = 0x2D to opcodes.go.

Step 2. Extend the string early-exit block in body.go's BinaryExpression case to a switch on the operator, routing == and != to a new walkStringEq method.

Step 3. Implement walkStringEq. Follow the control flow diagram exactly. Track b.blockDepth at each block, loop, if, and end byte. Emit hardcoded branch depths 0, 1, 2 — do not use b.blockDepth to compute them (they are relative to the internal structure, not the user-visible scope).

Step 4. Add tests:

func TestEndToEnd_StringEq(t *testing.T) {
    src := `
        export fn same(): bool   { return "hello" == "hello"; }
        export fn diff(): bool   { return "hello" == "world"; }
        export fn shorter(): bool { return "hi" == "hello"; }
    `
    runOne(t, src, "same",    nil, 1)

    runOne(t, src, "shorter", nil, 0)

func TestEndToEnd_StringNe(t *testing.T) {
    src := `
        export fn same(): bool { return "hello" != "hello"; }
        export fn diff(): bool { return "hello" != "world"; }
    `
    runOne(t, src, "same", nil, 0)
    runOne(t, src, "diff", nil, 1)
}

Step 5. Run the full suite to confirm no regressions:

go test ./internal/script/compiler/binary/... -v

Checklist Before Calling It Done

  • "hello" == "hello" returns 1 — same content, two separate allocations, pointer comparison would give 0 but byte comparison gives 1
  • "hello" == "world" returns 0 — same length, different bytes
  • "hi" == "hello" returns 0 — different lengths, fast path fires
  • "hello" != "world" returns 1
  • "hello" != "hello" returns 0
  • b.blockDepth is balanced — net zero change from walkStringEq
  • All previously passing tests still pass

Quiz

Check your understanding

1. Why can't string == be implemented as a single WASM instruction, even though i32 == can?

2. From inside the nested if at depth D+3, the mismatch branch uses br 2. Which construct does that target?

3. i32.load8_u is used instead of i32.load to read individual bytes. What does the "u" suffix mean here?

4. After the byte loop, isEqual holds 1 for equal and 0 for not-equal. For the != operator, which single WASM instruction converts this to the correct result?
