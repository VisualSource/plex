Lesson 52 – The export Keyword

Previous: Lesson 51 – The WASM Import Section

Every function you write in plex today ends up in the WASM export table. Write ten helper functions and your module has ten exports, all visible to the host — whether you intended them to be public or not. This lesson adds the export keyword so the programmer controls visibility explicitly.

Why This Matters

A WASM module's export table is its public API surface. The host cannot call anything that isn't exported. But the inverse also matters: anything you don't export is unreachable to the outside world — a module-level encapsulation boundary. Good language design makes you opt into publicity, not privacy.

The plex grammar already specifies this:

<functionDefinition> = <keyword:export>? <keyword:fn> <ident> <functionParams> ...

The ? means export is optional. But the compiler currently ignores it entirely — export isn't even in the tokenizer's keyword list, so the word would be scanned as an identifier, not a keyword. Today you implement the whole thing.

Where the Change Lives — All Four Layers

Adding export touches the compiler from top to bottom:

Tokenizer tokenizer.go line 425 — add "export" to the keyword list
AST ast_nodes.go — add Export bool field to FunctionDeclaration
Parser ast.go — handle export fn in parseStatement
Binary Backend helpers.go — only emit export entries for n.Export == true
Compare to mut — Export bool on FunctionDeclaration is structurally identical to Mut bool on Parameter. Both are boolean modifiers on a declaration node that the parser sets when it sees a particular keyword. The pattern recurs throughout compiler ASTs.

Layer 1 — Tokenizer

Open tokenizer.go and find the keyword switch (around line 425):

case "continue", "as", "false", "true", "import", "break", "from",
     "let", "return", "while", "impl", "if", "else", "struct", "fn", "mut":

Add "export" to this list. Without this change the tokenizer scans export as a TokenType_Ident, and isKeyword(t, "export") in the parser will never be true.

Layer 2 — AST

In ast_nodes.go, FunctionDeclaration currently has:

type FunctionDeclaration struct {
    Start, End Position
    Name       string
    Params     []*Parameter
    ReturnType *TypeExpr
    Body       AstNode
}

Add one field:

    Export     bool     // true if declared with "export fn"

Layer 3 — Parser

In ast.go, parseStatement currently has:

case isKeyword(t, "fn"):
    return p.parseFnDecl()

Add a new case above it to handle export fn:

case isKeyword(t, "export"):
    p.advance()                         // consume "export"
    if !isKeyword(p.peek(), "fn") {
        return nil, fmt.Errorf("expected 'fn' after 'export'")
    }
    decl, err := p.parseFnDecl()
    if err != nil {
        return nil, err
    }
    decl.Export = true
    return decl, nil
Why advance before checking fn? — parseStatement entered because peek() was export. After consuming it, the cursor sits on the next token. If that token isn't fn, it's a syntax error. This is the standard one-token-lookahead pattern used throughout the parser.

Layer 4 — Binary Backend

In helpers.go, collectSignatures currently unconditionally appends an export entry for every FunctionDeclaration:

case *script.FunctionDeclaration:
    sig, err := signatureOf(n, "")
    ...
    exports = append(exports, exportEntry{   ← always
        name: n.Name,
        kind: ExportFunc,
        idx:  uint32(len(funcs)),
    })
    sigs   = append(sigs, sig)
    funcs  = append(funcs, n)

Gate the export on n.Export:

case *script.FunctionDeclaration:
    sig, err := signatureOf(n, "")
    if err != nil { return nil, nil, nil, err }
    if n.Export {
        exports = append(exports, exportEntry{name: n.Name, kind: ExportFunc})
    }
    sigs  = append(sigs, sig)
    funcs = append(funcs, n)

Note that the idx field is intentionally omitted — the fix-up loop in module.go fills it in from funcIndexes after the full index map is built. Both exported and unexported functions still get compiled into the code section; they're just not visible to the host.

The test suite will break immediately after step 4. Every existing test program uses bare fn, which now means "private". The test harness calls mod.ExportedFunction("name"), which returns nil for unexported functions, causing a panic or a nil-dereference. You must update the test programs as part of this task — see Step 5 below.

Implementation Task

Task — implement export end-to-end

Step 1. In tokenizer.go line 425, add "export" to the keyword case.

Step 2. In ast_nodes.go, add Export bool to FunctionDeclaration.

Step 3. In ast.go parseStatement, add the export case shown above (before the fn case).

Step 4. In helpers.go collectSignatures, gate the export append on n.Export.

Step 5 — migrate the test suite. The word fn is used only in plex source inside the test file's backtick strings; Go uses func. A targeted sed replaces every plex function declaration:

sed -i 's/\bfn /export fn /g' internal/script/compiler/binary/end_to_end_test.go

Verify by grepping that no bare fn (with space) remains inside the test strings. The import-section test's program already has an import statement before the function — sed will prefix that fn too, which is correct.

Step 6 — add a visibility test. Verify that an unexported function really is hidden:

func TestExport_VisibilityBoundary(t *testing.T) {
    src := `
        export fn public_fn(): i64 { return 1; }
               fn private_fn(): i64 { return 2; }
    `
    ast, err := script.Parse(strings.NewReader(src))
    if err != nil { t.Fatal(err) }

    wasm, err := binary_wasm.CompileProgram(ast)
    if err != nil { t.Fatal(err) }

    ctx := t.Context()
    r := wazero.NewRuntime(ctx)
    defer r.Close(ctx)

    mod, err := r.Instantiate(ctx, wasm)
    if err != nil { t.Fatalf("instantiate: %v", err) }

    if mod.ExportedFunction("public_fn") == nil {
        t.Fatal("public_fn should be exported")
    }
    if mod.ExportedFunction("private_fn") != nil {
        t.Fatal("private_fn should NOT be exported")
    }
}

Step 7. Run the full suite:

go test ./internal/script/compiler/binary/... -v

All existing tests (now using export fn) should pass. TestExport_VisibilityBoundary should also pass.

What Didn't Change

Unexported functions are compiled into the code section exactly like exported ones. The function body, local variables, and internal call instructions are unaffected — only the export table entry is withheld. An exported function can still call an unexported helper without restriction; WASM's call instruction uses the absolute function index, which is module-internal and doesn't go through the export table.

Struct methods are always private. The StructImplStatement branch of collectSignatures never creates export entries — method names are mangled (__TypeName__methodName) and are called only via the compiler-generated dispatch, never directly by the host. This hasn't changed.

Checklist Before Calling It Done

  • TestExport_VisibilityBoundary passes — public_fn is exported, private_fn is not
  • All previously passing tests still pass (every function they call is now export fn)
  • A plex program with no export fn at all compiles to a module with no function exports (only memory/global exports if heap is used)
  • Unexported functions can still be called by other plex functions in the same module
