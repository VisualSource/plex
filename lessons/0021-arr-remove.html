Lesson 21 – arr.remove(i)

Removing an element from an array means shifting everything after it one slot to the left — a compiler-generated loop inside a builtin.

This lesson

  2. Why the return value must be saved before shifting
  3. The shift loop in WAT — internal labels vs the break stack
  4. Implementation sketch

1. What remove must do

Given arr = [10, 20, 30, 40] and arr.remove(1), the array should become [10, 30, 40] and the function should return 20.

In terms of memory operations:

1
Load and save the element at index i (the return value).
2
Shift every element from i+1 to len-1 one slot to the left: arr[j] = arr[j+1].
3
Decrement the count (stored at offset 0).
4
Leave the saved element on the WAT value stack (the return value).

Memory before and after remove(1) on a i64[] (elemSize = 8):

OffsetBeforeAfter
04 (count)3 (count)
410 (index 0)10 (index 0)
1220 (index 1 ← removed)30 (shifted from index 2)
2030 (index 2)40 (shifted from index 3)
2840 (index 3)40 (stale — count hides it)

The stale element at offset 28 is never zeroed — it's hidden by the decremented count. Any subsequent read or append stays within the new count.

2. Why the return value must be saved first

The shift loop overwrites arr[i] with arr[i+1]. If you start shifting before saving, the original element is gone. You must load it into a temp local before the first shift.

;; WRONG — shifts first, then tries to load original
;; ... shift loop ...
ELEM.load   ;; arr[i] now contains arr[i+1] — wrong value returned

;; CORRECT — load first, shift second
;; load arr[i] into a temp local
;; ... shift loop ...
;; push temp local as return value

This means you need two additional temp locals beyond the array pointer: one for the return value (element type) and one for the shift cursor (i32).

3. The shift loop in WAT

The shift is a simple counting loop. In plex pseudocode it looks like:

let cursor = i;
while cursor < (old_len - 1) {
    arr[cursor] = arr[cursor + 1];
    cursor++;
}

In WAT this becomes a (block (loop …)) pair — the same structure as a compiled while statement. But there's one crucial difference: this loop is compiler-generated, not user-written. It must not interact with the user's break stack.

Internal vs user-visible labels — The break stack (c.breakStack) exists so that a user's break statement can escape the nearest enclosing while loop. A compiler-generated loop inside a builtin must use its own labels but must not push them onto the break stack. If it did, a break inside remove would try to escape the shift loop instead of the user's while loop. Use c.labelCount directly to allocate unique labels, without calling pushBreakLabel. 
;; allocate internal labels (do NOT push to breakStack)
shiftBreak := fmt.Sprintf("$rem_break_%d", c.labelCount)
shiftLoop  := fmt.Sprintf("$rem_loop_%d", c.labelCount)
c.labelCount++

c.emit(fmt.Sprintf("(block %s", shiftBreak))
c.depth++
c.emit(fmt.Sprintf("(loop %s", shiftLoop))
c.depth++

;; ... shift body ...

c.depth--
c.emit(")") // end loop
c.depth--
c.emit(")") // end block

The per-iteration copy

Each iteration copies one element: arr[cursor] = arr[cursor+1]. In WAT, ELEM.store consumes (address, value) from the stack. So you must push the destination address first, then load the source value:

;; ── push destination address: ptr + 4 + cursor*elemSize ──
local.get $arr
i32.const 4
i32.add
local.get $cursor
i32.const ELEM_SIZE
i32.mul
i32.add

;; ── push source value: arr[cursor+1] ──
local.get $arr
i32.const 4
i32.add
local.get $cursor
i32.const 1
i32.add
i32.const ELEM_SIZE
i32.mul
i32.add
ELEM_TYPE.load

;; ── store (dst, value already on stack) ──
ELEM_TYPE.store

Loop exit condition and cursor increment

;; exit if cursor >= old_len - 1
local.get $cursor
local.get $new_len   ;; = old_len - 1 (pre-computed)
i32.ge_s
br_if $rem_break_N

;; ... copy instruction above ...

;; cursor++
local.get $cursor
i32.const 1
i32.add
local.set $cursor

br $rem_loop_N

4. Full implementation sketch

Putting all four steps together:

case "remove":
    elemType := getWasmType(t.Element)
    elemSize := sizeOf(elemType)

    // temp locals
    arrTmp := fmt.Sprintf("__rem_arr_%d", c.tempVars)
    idxTmp := fmt.Sprintf("__rem_idx_%d", c.tempVars)
    retTmp := fmt.Sprintf("__rem_ret_%d", c.tempVars)
    lenTmp := fmt.Sprintf("__rem_len_%d", c.tempVars)
    curTmp := fmt.Sprintf("__rem_cur_%d", c.tempVars)
    c.tempVars++
    c.locals = append(c.locals,
        Local{Name: arrTmp, Type: "i32"},
        Local{Name: idxTmp, Type: "i32"},
        Local{Name: retTmp, Type: elemType},
        Local{Name: lenTmp, Type: "i32"},
        Local{Name: curTmp, Type: "i32"},
    )

    // save array pointer
    if err := c.Compile(callee.Object); err != nil { return err }
    c.emit(fmt.Sprintf("local.set $%s", arrTmp))

    // save index (compile arg[0], wrap i64→i32)
    if err := c.Compile(n.Args[0]); err != nil { return err }
    c.emit("i32.wrap_i64")
    c.emit(fmt.Sprintf("local.set $%s", idxTmp))

    // step 1: load and save the element to return
    c.emit(fmt.Sprintf("local.get $%s", arrTmp))
    c.emit("i32.const 4")
    c.emit("i32.add")
    c.emit(fmt.Sprintf("local.get $%s", idxTmp))
    c.emit(fmt.Sprintf("i32.const %d", elemSize))
    c.emit("i32.mul")
    c.emit("i32.add")
    c.emit(elemType + ".load")
    c.emit(fmt.Sprintf("local.set $%s", retTmp))

    // save new_len = old_len - 1
    c.emit(fmt.Sprintf("local.get $%s", arrTmp))
    c.emit("i32.load")
    c.emit("i32.const 1")
    c.emit("i32.sub")
    c.emit(fmt.Sprintf("local.set $%s", lenTmp))

    // init cursor = idx
    c.emit(fmt.Sprintf("local.get $%s", idxTmp))
    c.emit(fmt.Sprintf("local.set $%s", curTmp))

    // step 2: shift loop (internal labels — NOT on break stack)
    bl := fmt.Sprintf("$rem_break_%d", c.labelCount)
    ll := fmt.Sprintf("$rem_loop_%d", c.labelCount)
    c.labelCount++

    c.emit(fmt.Sprintf("(block %s", bl))
    c.depth++
    c.emit(fmt.Sprintf("(loop %s", ll))
    c.depth++

    // exit check
    c.emit(fmt.Sprintf("local.get $%s", curTmp))
    c.emit(fmt.Sprintf("local.get $%s", lenTmp))
    c.emit("i32.ge_s")
    c.emit(fmt.Sprintf("br_if %s", bl))

    // dst address: arr + 4 + cursor*elemSize
    c.emit(fmt.Sprintf("local.get $%s", arrTmp))
    c.emit("i32.const 4")
    c.emit("i32.add")
    c.emit(fmt.Sprintf("local.get $%s", curTmp))
    c.emit(fmt.Sprintf("i32.const %d", elemSize))
    c.emit("i32.mul")
    c.emit("i32.add")

    // src value: arr[cursor+1]
    c.emit(fmt.Sprintf("local.get $%s", arrTmp))
    c.emit("i32.const 4")
    c.emit("i32.add")
    c.emit(fmt.Sprintf("local.get $%s", curTmp))
    c.emit("i32.const 1")
    c.emit("i32.add")
    c.emit(fmt.Sprintf("i32.const %d", elemSize))
    c.emit("i32.mul")
    c.emit("i32.add")
    c.emit(elemType + ".load")

    // store dst ← src
    c.emit(elemType + ".store")

    // cursor++
    c.emit(fmt.Sprintf("local.get $%s", curTmp))
    c.emit("i32.const 1")
    c.emit("i32.add")
    c.emit(fmt.Sprintf("local.set $%s", curTmp))
    c.emit(fmt.Sprintf("br %s", ll))

    c.depth--
    c.emit(")")  // end loop
    c.depth--
    c.emit(")")  // end block

    // step 3: decrement count
    c.emit(fmt.Sprintf("local.get $%s", arrTmp))
    c.emit(fmt.Sprintf("local.get $%s", lenTmp))
    c.emit("i32.store")

    // step 4: leave return value on stack
    c.emit(fmt.Sprintf("local.get $%s", retTmp))

Task

Task
  1. Add the "remove" case inside the TypeKind_Array branch of the FunctionCall → MemberAccess compiler path.
  2. Write a compiler test that creates a 3-element i64[], removes index 1, checks the return value equals 20, and checks the new length is 2.
  3. Write a second test that removes the first element (index 0) and verifies the remaining elements shifted correctly.

Suggested test program

fn test(): i64 {
    let arr: i64[] = [10, 20, 30];
    let removed = arr.remove(1);
    // arr is now [10, 30], removed == 20
    return removed;
}

Expected return: 20. Check arr.len() returns 2 and arr[0] returns 10.

Out-of-bounds is still your problem — calling arr.remove(i) where i >= arr.len() reads out of bounds memory and shifts garbage. The compiler doesn't check this; the WAT runtime doesn't either. A defensive caller should check first.

Quiz

Check your understanding

1. Why must the element be loaded into a temp local before the shift loop starts?

2. Why do we use i32.wrap_i64 on the index argument before storing it in $idx?

3. The shift loop uses c.labelCount directly instead of pushBreakLabel. What goes wrong if it used pushBreakLabel instead?

4. The shift loop exits when cursor >= new_len (using i32.ge_s). Why new_len (= old_len − 1) rather than old_len?

What comes next

With remove done, the array method trio is complete. The language now has all the basic collection operations a scripting language needs.

The next interesting frontier is numeric type coercions — an as keyword that lets you convert between i64, f64, i32, and f32. WAT has precise instructions for each direction of conversion (i64.extend_i32_s, i32.wrap_i64, f64.convert_i64_s, i64.trunc_f64_s, …). Adding as requires changes in the parser, typechecker, and compiler — a good full-stack lesson.
