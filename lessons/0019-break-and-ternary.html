1. The problem with relative branch indices

Your current while loop emits relative branch targets:

(block           ;; index 1 (outer)
  (loop           ;; index 0 (inner)
    ;; condition
    i32.eqz
    br_if 1       ;; exit outer block
    ;; body
    br 0          ;; jump back to loop
  )
)

The number in br N is a depth index — 0 means "the nearest enclosing block/loop", 1 means "one level up". This works fine as long as the body is flat. But the moment you put a break somewhere deep inside the body, br 1 no longer reaches the outer block — it only exits whatever is immediately around it.

The depth problem If the body contains an if and the user writes break inside it, the compiler would need to know its current nesting depth to emit the right number. That's fragile and hard to track correctly across recursive Compile calls.

The solution is named labels. WAT lets you label any block, loop, or if:

(block $break_0
  (loop $loop_0
    ;; condition
    i32.eqz
    br_if $break_0   ;; exit by name — works at any depth
    ;; body
    br $loop_0       ;; back to loop top by name
  )
)

Now a break anywhere inside the body can simply emit br $break_0 regardless of how deeply nested it is — the assembler resolves the label.

2. The label counter pattern

You need unique label names across nested loops. The standard approach is a monotonically-increasing counter on the Compiler struct:

type Compiler struct {
    // ... existing fields ...
    labelCount int
    breakStack []string
}

Each time you open a while loop, you allocate a fresh label pair and push the break label onto the stack:

func (c *Compiler) pushBreakLabel() (string, string) {
    n := c.labelCount
    c.labelCount++
    bl := fmt.Sprintf("$break_%d", n)
    ll := fmt.Sprintf("$loop_%d", n)
    c.breakStack = append(c.breakStack, bl)
    return bl, ll
}

func (c *Compiler) popBreakLabel() {
    c.breakStack = c.breakStack[:len(c.breakStack)-1]
}

func (c *Compiler) currentBreakLabel() string {
    return c.breakStack[len(c.breakStack)-1]
}
Stack, not counter alone — a stack handles nested loops. The innermost loop's break label is always at the top. currentBreakLabel() peeks at the top without popping, so an inner break escapes the nearest loop, not a random outer one.

Task A (three small changes)

  2. Add the three helper methods above (pushBreakLabel, popBreakLabel, currentBreakLabel).
  3. Update the WhileStatement case to use named labels and call pushBreakLabel / popBreakLabel.
  4. Add a BreakStatement case that emits br $break_N.

Updated WhileStatement

case *script.WhileStatement:
    bl, ll := c.pushBreakLabel()
    defer c.popBreakLabel()

    c.emit(fmt.Sprintf("(block %s", bl))
    c.depth++
    c.emit(fmt.Sprintf("(loop %s", ll))
    c.depth++

    if err := c.Compile(n.Condition); err != nil {
        return err
    }
    c.emit("i32.eqz")
    c.emit(fmt.Sprintf("br_if %s", bl))

    if err := c.Compile(n.Body); err != nil {
        return err
    }
    c.emit(fmt.Sprintf("br %s", ll))
    c.depth--
    c.emit(")") // end loop
    c.depth--
    c.emit(")") // end block

BreakStatement case

case *script.BreakStatement:
    if len(c.breakStack) == 0 {
        return fmt.Errorf("break outside of loop")
    }
    c.emit(fmt.Sprintf("br %s", c.currentBreakLabel()))
defer for cleanup — using defer popBreakLabel() immediately after pushBreakLabel() ensures the label is removed from the stack even if compilation of the loop body returns an error early. This is idiomatic Go for paired push/pop operations.

3. WAT's value-producing if

An ordinary WAT if is a statement — it executes a branch but doesn't leave a value on the stack. To get a value out, you add a result type:

Statement ifValue-producing if
(if
  (then ...)
  (else ...)
)
 
(if (result i64)
  (then ... ; must leave one i64)
  (else ... ; must leave one i64)
)
Stack unchanged after if One i64 is on the stack after if

A plex ternary x > 0 ? x : -x maps directly:

;; x > 0 ? x : -x  (x is local $x : i64)
local.get $x
i64.const 0
i64.gt_s
(if (result i64)
  (then
    local.get $x
  )
  (else
    i64.const 0
    local.get $x
    i64.sub
  )
)
;; one i64 is now on the stack
Both branches must agree — if the result type is i64, both then and else must leave exactly one i64 on the stack. The typechecker already enforces that both sides of a ternary have the same type (typecheck.go:554), so by the time you reach the compiler this is guaranteed.

    c.depth--

    c.depth++

    }
    c.depth--
    c.emit(")")

    c.depth--
    c.emit(")") // end if

Where this fits

With these two cases, every node in your AST has a compiler implementation. The language now has:

  • All arithmetic, comparison, and logical operators
  • If / while / break control flow
  • Ternary expressions that produce values
  • Functions, structs, methods, arrays, strings

That's a complete, working scripting language. The next frontier is making it more usable — string operations (concatenation, length, indexing) are the most user-visible gap, and they'll take you into runtime helper functions.
