1. What the typechecker already knows

Open typeschecker/typecheck.go and look at the FunctionCall → MemberAccess case (around line 313). The typechecker already resolves three built-in methods for arrays and one for strings:

ExpressionType-checked returnCompiler?
arr.len()TypeKind_Int (i64)not yet
arr.append(elem)TypeKind_Voidnot yet
arr.remove(i)element typenot yet
str.len()TypeKind_Int (i64)not yet

The compiler's FunctionCall → MemberAccess path currently only handles struct methods — it looks up the callee in c.structs and panics on anything else. Our job is to intercept arrays and strings before hitting the struct lookup.

2. arr.len() — one load, always O(1)

Recall the array layout from Lesson 9:

offset 0:   i32 count   ← element count stored here
offset 4:   elem[0]
offset 4+N: elem[1]
...

The array already stores its length at offset 0. The array literal compiler emits:

i32.const 2      ;; element count
i32.store         ;; write at base pointer

So arr.len() is trivially:

;; arr.len() where arr is an i32 pointer
local.get $arr
i32.load          ;; read the 4-byte count
i64.extend_i32_s  ;; promote to i64 (TypeKind_Int = i64)
Why extend? Array length is stored as i32 in memory (4 bytes), but TypeKind_Int maps to i64 in getWasmType. Every integer variable in plex is 64-bit, so the result of len must be too — otherwise any arithmetic like arr.len() - 1 would have a type mismatch.

3. Why str.len() needs a layout change

Strings are currently stored as null-terminated byte sequences in the WAT data segment:

(data (i32.const 8) "hello\00")

The string pointer is just the i32 offset (8 here). The data starts at that address. There is no length stored anywhere.

To count the length you would have to scan forward until you hit the null byte — O(n) every time. For a language where you can call s.len() in a loop, that's a hidden performance trap.

The fix is to store the length as 4 bytes immediately before the data pointer:

offset 4:   \05\00\00\00  ← i32 length (5) in little-endian
offset 8:   h e l l o    ← string ptr = 8 (unchanged!)
offset 13:  \00          ← null terminator

The string pointer still points to the data (offset 8). The host-side print function continues to work unchanged because it receives the same kind of pointer it always has.

str.len() loads the 4 bytes just before the pointer:

;; str.len() where str is an i32 pointer to the first byte
local.get $str
i32.const 4
i32.sub           ;; step back 4 bytes to the length field
i32.load          ;; read the 4-byte length
i64.extend_i32_s  ;; promote to i64

4. Adding a length prefix to static strings

Two places need changing: the prepass (where offsets are calculated) and the emission (where data segments are written).

Prepass change

In prepass, the StringLiteral case currently does:

// OLD
c.strings = append(c.strings, stringEntry{
    value:  n.Value,
    offset: c.dataPtr,
})
c.dataPtr += len(n.Value) + 1   // +1 for \00

Change it so the offset points to the data (after the 4-byte length), and advance dataPtr by the extra 4 bytes:

// NEW
c.strings = append(c.strings, stringEntry{
    value:  n.Value,
    offset: c.dataPtr + 4,   // ptr points past the length field
})
c.dataPtr += 4 + len(n.Value) + 1

Emission change

In CompileProgram, strings are currently emitted as:

c.emit(fmt.Sprintf("(data (i32.const %d) \"%s\\00\")", entry.offset, escaped))

The data segment must now start 4 bytes before entry.offset, with the length encoded as 4 little-endian bytes:

// encode length as little-endian 4 bytes
n := len(entry.value)
lenBytes := fmt.Sprintf("%02x\\%02x\\%02x\\%02x",
    n&0xff, (n>>8)&0xff, (n>>16)&0xff, (n>>24)&0xff)

c.emit(fmt.Sprintf(
    "(data (i32.const %d) \"\\%s%s\\00\")",
    entry.offset-4,   // start at the length field
    lenBytes,
    escaped,
))
Little-endian encoding in WAT data — WAT data segments use \HH two-hex-digit byte escapes. WebAssembly is always little-endian, so the 4-byte integer 5 is written as \05\00\00\00 (least significant byte first). An i32 in memory can be any of the four bytes; i32.load reassembles them in the correct order.
Snapshot breakage — changing the string layout means every existing WAT snapshot that includes a string literal will differ. Run go test ./internal/script/compiler/... -update (or however your test suite updates snapshots) after implementing.

5. arr.append() — growing a logical list

append adds one element to the end of an array. In memory terms:

  1. Read the current count from offset 0.
  2. Calculate the write address: base + 4 + count * elemSize.
  3. Store the new element there.
  4. Increment the count at offset 0.

There is a critical constraint: the allocation made by the array literal only covers 4 + initialCount * elemSize bytes. Appending beyond that overwrites adjacent heap memory.

No bounds checking (yet) — plex has no safety net here. Calling arr.append(x) when the array is full corrupts the heap silently. Defensive usage: allocate the array with extra capacity upfront. A future lesson could add a capacity/length split (like Go slices), but for now we implement the fast, unsafe version.

The WAT is tricky because you need the old length (for the write address) and then immediately increment it. Use a local temp or the transaction pattern. The simplest approach compiles the object twice (once to read length, once as the store base):

case "append":
    // element type comes from the array type
    elemType := getWasmType(t.Element)
    elemSize := sizeOf(elemType)

    // need a temp local to hold array ptr (used 3 times)
    tmpName := fmt.Sprintf("__append_tmp%d", c.tempVars)
    c.tempVars++
    c.locals = append(c.locals, Local{Name: tmpName, Type: "i32"})

    if err := c.Compile(callee.Object); err != nil {
        return err
    }
    c.emit(fmt.Sprintf("local.tee $%s", tmpName)) // save ptr, keep on stack

    // read old count
    c.emit(fmt.Sprintf("local.get $%s", tmpName))
    c.emit("i32.load")                // old count on stack

    // compute write address: ptr + 4 + oldCount*elemSize
    c.emit(fmt.Sprintf("i32.const %d", elemSize))
    c.emit("i32.mul")
    c.emit("i32.const 4")
    c.emit("i32.add")
    c.emit(fmt.Sprintf("local.get $%s", tmpName))
    c.emit("i32.add")                // final write address on stack

    // compile element value (second operand to store)
    if err := c.Compile(n.Args[0]); err != nil {
        return err
    }
    c.emit(elemType + ".store")      // write element

    // increment count: ptr, old count+1, store
    c.emit(fmt.Sprintf("local.get $%s", tmpName))
    c.emit(fmt.Sprintf("local.get $%s", tmpName))
    c.emit("i32.load")
    c.emit("i32.const 1")
    c.emit("i32.add")
    c.emit("i32.store")               // update count
