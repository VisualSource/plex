Structs & Native Functions

Compound values, method dispatch, and the host/guest boundary

Three bugs to fix first

1. Closure env — eval.go:128: callEnv := NewEnvironment(env) should be NewEnvironment(fn.Env). Using the call-site scope instead of the closure's scope breaks any function that references an outer variable.

2. While catches return — eval.go:108: the returnSignal check inside WhileStatement consumes the signal rather than letting it propagate to the enclosing function. Remove that branch; only FunctionCall should unwrap a returnSignal.

3. Format verb — eval.go:148: %l is not a valid Go verb. Change to %T to print the node's type name.

What Makes a Language Practical

Your interpreter can run functions and loops. Two things are still missing before you can write real programs in plex:

  1. Structs — a way to group related values under named fields
  2. Native functions — a way to call Go code from plex (for I/O, math, and anything the language can't provide for itself)

These teach two foundational runtime concepts: compound values and the host/guest boundary.

Part 1: Struct Instances as Runtime Values

At runtime, a struct instance is just a map from field name to value. The struct declaration defines the shape; constructing an instance fills the map.

// StructValue is a live instance — a map of field name → value
type StructValue struct {
    TypeName string
    Fields   map[string]Value
}
func (s *StructValue) Truthy() bool    { return true }
func (s *StructValue) String() string { return s.TypeName + "{...}" }

// StructType holds the declared shape — stored in the env when "struct" is eval'd
type StructType struct {
    Name    string
    Fields  []string        // ordered field names
    Methods map[string]FunctionValue
}
func (s StructType) Truthy() bool    { return true }
func (s StructType) String() string { return "<type:" + s.Name + ">" }

Evaluating a StructStatement creates a StructType and binds it in the environment. Evaluating a StructImplStatement finds the existing StructType and adds methods to it:

case *script.StructStatement:
    fields := make([]string, 0, len(n.Fields))
    for _, f := range n.Fields {
        fields = append(fields, f.(*script.Parameter).Name)
    }
    env.Set(n.Name, StructType{Name: n.Name, Fields: fields, Methods: make(map[string]FunctionValue)})
    return NullValue{}, nil

case *script.StructImplStatement:
    v, ok := env.Get(n.Name)
    if !ok { return nil, fmt.Errorf("impl: unknown type %s", n.Name) }
    st, ok := v.(StructType)
    if !ok { return nil, fmt.Errorf("%s is not a struct type", n.Name) }
    for _, m := range n.Methods {
        fn := m.(*script.FunctionDeclaration)
        st.Methods[fn.Name] = FunctionValue{Params: fn.Params, Body: fn.Body, Env: env}
    }
    env.Assign(n.Name, st) // write back with methods attached
    return NullValue{}, nil

Part 2: Construction and Field Access

When plex code calls Point(1, 2), the callee resolves to a StructType — not a FunctionValue. The FunctionCall case needs to handle both:

case *script.FunctionCall:
    calleeVal, err := Eval(n.Callee, env)
    if err != nil { return nil, err }

    switch callee := calleeVal.(type) {

    case StructType: // construction: Point(1, 2)
        instance := &StructValue{TypeName: callee.Name, Fields: make(map[string]Value)}
        for i, fieldName := range callee.Fields {
            arg, err := Eval(n.Args[i], env)
            if err != nil { return nil, err }
            instance.Fields[fieldName] = arg
        }
        return instance, nil

    case FunctionValue: // normal call (existing logic)
        // ... move your existing function call code here
    }
    return nil, fmt.Errorf("not callable")

Field access (point.x) is already parsed as MemberAccess. Now eval it:

case *script.MemberAccess:
    obj, err := Eval(n.Object, env)
    if err != nil { return nil, err }
    instance, ok := obj.(*StructValue)
    if !ok { return nil, fmt.Errorf("%s is not a struct", n.Field) }
    v, ok := instance.Fields[n.Field]
    if !ok { return nil, fmt.Errorf("no field %s", n.Field) }
    return v, nil

Part 3: Method Dispatch

When plex code calls point.move(1, 2), the parser produces a FunctionCall whose Callee is a MemberAccess. The key question: how does the method know what self is?

The answer: detect the pattern during call evaluation — if the callee is a MemberAccess, eval the object, look up the method on the struct type, and inject self into the call environment:

case *script.FunctionCall:
    // check for method call: callee is MemberAccess
    if ma, ok := n.Callee.(*script.MemberAccess); ok {
        obj, err := Eval(ma.Object, env)
        if err != nil { return nil, err }
        instance, ok := obj.(*StructValue)
        if !ok { /* fall through to field-value-as-fn case below */ }

        if ok {
            // look up method on the struct's type
            typVal, _ := env.Get(instance.TypeName)
            st := typVal.(StructType)
            method, ok := st.Methods[ma.Field]
            if !ok { return nil, fmt.Errorf("no method %s", ma.Field) }

            callEnv := NewEnvironment(method.Env)
            callEnv.Set("self", instance) // inject self
            for i, param := range method.Params {
                arg, err := Eval(n.Args[i], env)
                if err != nil { return nil, err }
                callEnv.Set(param.(*script.Parameter).Name, arg)
            }
            _, err = Eval(method.Body, callEnv)
            if ret, ok := err.(returnSignal); ok { return ret.value, nil }
            return NullValue{}, err
        }
    }
    // ... normal function call below
self is just a convention
There's nothing magic about self — it's just a name injected into the call environment. Plex methods access it like any other variable. Python does the same thing with self as an explicit first parameter; Go uses the receiver; Rust uses &self. All three are the same concept with different syntax.

Part 4: Native Functions — the Host/Guest Boundary

Every scripting language needs a way for the host (Go) to expose functions to the guest (plex). The pattern is simple: a native function is a Go func wrapped in a Value.

type NativeFunction struct {
    Name string
    Fn   func(args []Value) (Value, error)
}
func (n NativeFunction) Truthy() bool    { return true }
func (n NativeFunction) String() string { return "<native:" + n.Name + ">" }

Add a third case to the FunctionCall handler:

case NativeFunction:
    args := make([]Value, len(n.Args))
    for i, arg := range n.Args {
        v, err := Eval(arg, env)
        if err != nil { return nil, err }
        args[i] = v
    }
    return callee.Fn(args)

Now expose builtins by pre-populating the global environment before running any plex code:

func NewGlobalEnv() *Environment {
    env := NewEnvironment(nil)

    env.Set("print", NativeFunction{Name: "print", Fn: func(args []Value) (Value, error) {
        parts := make([]string, len(args))
        for i, a := range args { parts[i] = a.String() }
        fmt.Println(strings.Join(parts, " "))
        return NullValue{}, nil
    }})

    env.Set("str", NativeFunction{Name: "str", Fn: func(args []Value) (Value, error) {
        if len(args) != 1 { return nil, fmt.Errorf("str: expected 1 arg") }
        return StringValue{V: args[0].String()}, nil
    }})

    return env
}
This is how every embedded language works
Lua, JavaScript (V8), Python, Wren — all expose host APIs by pre-populating the global environment with native callables. The function signature func(args []Value) (Value, error) is the boundary: plex values in, plex values out, Go error if something goes wrong.
